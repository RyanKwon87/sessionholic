# 지원 범위와 한계

세션홀릭(Sessionholic)은 개인이 소유한 macOS 중심 환경에서 로컬 native CLI 세션을 모아 보고, 기존 세션에 연결하거나 새 환경에서 맥락을 이어가는 self-hosted 도구입니다. 여러 사용자가 공유하는 서비스나 공개 인터넷 서비스가 아닙니다. macOS 실행 호스트에는 사용자가 직접 설치하고 로그인한 Claude Code 또는 Codex CLI, Python, tmux가 필요합니다. Windows PC의 저장 기록은 기기 연결과 실행 확인을 구분하며 현재 실행을 확인하지 못하면 `실행 확인 전`으로 표시합니다. Windows에서는 정확한 기존 Codex 실행 서버가 확인되면 텍스트 입력·터미널 연결·응답 중단·종료를 제공합니다. 서버에 로드되지 않은 Codex 기록은 같은 프로젝트의 서버가 PC에서 실행 중일 때만 보드 터미널에서 다시 엽니다. 관리자 SSH 세션의 내장 실행은 쓰지 않으므로 서버가 꺼져 있으면 새 세션으로 그 프로젝트를 먼저 열어야 합니다. 실행된 적 있는 프로젝트 서버가 꺼져 있으면 해당 기록에 그 사실을 표시하고, 최근 7일 안에 쓴 프로젝트면 기기 칩도 `확인 필요`로 바뀝니다. 서버 밖에서 도는 `codex exec`는 쓰기 잠금을 연 Codex 프로세스를 Windows 재시작 관리자로 확인해 작업 중으로 표시하며(잠금은 잡지 않음), 수집 주기보다 짧은 실행은 놓칠 수 있습니다. 다른 Codex 프로세스가 쓰고 있는 기록은 다시 열지 않습니다. Windows Claude는 PC에서 실행 중이 아닌 대화형 기록만 보드 터미널에서 `--resume`으로 다시 열고, 그 터미널을 통해 텍스트를 보냅니다. PC에서 실행 중인 대화형 Claude에는 연결하지 않으며, 원본 프로세스가 확인된 경우 실행 종료만 지원합니다. PC에서 실행 중인 백그라운드 Claude는 Mac처럼 보드 터미널로 연결(attach)해 텍스트를 보내며, 보내기·질문 불러오기·명령이 터미널이 없으면 먼저 연결합니다. 백그라운드 Claude의 첨부·기기 간 이전은 지원하지 않습니다. 새 세션은 `hosts.json`의 `launcher`에 적은 PC 실행 명령만 번호 메뉴로 엽니다. 터미널 보조키는 Windows에서 ⌘ 없이 Ctrl·Alt로 표시합니다. 호스트 간 기능은 사용자가 설정한 SSH 연결을 사용합니다.

## 세션 목록의 묶음

- 별도의 작업 탭은 없습니다. 세션에서 목표를 추정해 카드로 만들던 자동 작업 화면은 대부분 세션 하나를 다시 보여 주는 데 그쳐 내렸습니다. 화면 밖에서 대화를 읽던 자동 작업 관찰도 기본으로 꺼져 있으며(`--auto-work`로 켤 수 있음), 이전에 저장한 작업 기록은 지우지 않습니다.
- 세션 목록은 **답 필요 → 작업 중 → 최근 끝남 → 이전** 순입니다. 최근 끝남은 3시간 안에 멈춘(열림·완료·닫힘) 세션이고, 실행 상태를 확인하지 못한 기록은 이전에 둡니다. 3일 지난 기록을 숨기는 기본 기간은 이전 묶음에만 적용해, 오래 기다린 답 필요 세션도 목록에 남습니다. 답 필요·작업 중·최근 끝남 묶음 안은 화면에 보이는 제목 가나다순(숫자는 크기순)이라 세션이 갱신돼도 자리가 바뀌지 않으며, 순서는 제목 수정으로 바꿉니다. 이전 묶음은 이 보드에서 대화를 가장 최근에 연 순서(어느 기기에서 열었든, `session-opened.json`), 연 적이 없으면 최근 갱신 순입니다. 대화를 열면 그 세션이 이전 묶음 맨 위로 옵니다. 목록 옆에 대화를 띄우는 넓은 화면에서는 보고 있는 동안 자리를 지키고, 다른 대화를 열거나 목록만 보이면 올라갑니다. 같은 세션을 1분 안에 다시 열면 기록하지 않고, 다른 기기에는 다음 목록 갱신 때 반영됩니다.
- 보드에서 끝낸 세션은 목록에서도 정리합니다. 세션 관리의 **실행 종료**가 확인됐거나 사용자가 실행 중인 그 세션의 보드 터미널을 닫으면, 최근 끝남에 남기지 않고 3일 지난 기록처럼 기본 목록에서 내립니다. 기존 작업에 붙은 연결의 **연결 닫기**는 작업을 끝내지 않으므로, 그 세션이 작업 중·답 필요가 아닐 때만 정리합니다. 이미 끝난 터미널을 닫는 것은 정리하지 않습니다. 기록은 보드 상태 폴더(`session-tidied.json`)에 저장돼 모든 기기에서 같습니다. 실행과 대화 기록은 건드리지 않고, 검색이나 '오래된 기록 포함'으로 볼 수 있습니다. 정리한 뒤 2분 안의 갱신은 종료 과정에서 생긴 것으로 보고, 그 뒤 다시 갱신되면(새 메시지 등) 목록에 돌아옵니다. 작업 중·답 필요 세션은 정리 여부와 상관없이 보입니다. 보드에서 연 새 세션은 그 세션에 추정으로 연결돼 있어도 정리 대상에 넣습니다(표시만 바뀌므로). 실행 기기가 잠들어 끊긴 경우처럼 보드에서 끝내지 않은 세션은 그대로 최근 끝남에 남습니다.
- 카드를 길게 누르거나(오른쪽 클릭) 세션 관리에서 **목록에서 지우기**를 고르면, 정리와 달리 다시 갱신돼도 목록에 돌아오지 않습니다(`session-removed.json`, 모든 기기에서 같음). 답 필요·작업 중으로 바뀌거나 검색·'3일 지난 대화도 보기'를 켜도 숨김을 유지하고, 알림은 그대로 옵니다. 정리만 된 세션도 같은 메뉴로 지울 수 있습니다. 필터의 **지운 세션 포함**을 직접 켜면 오래된 지운 세션도 '지움' 표시와 함께 보이고, 같은 메뉴의 **목록에 다시 표시**로 되돌립니다(보드에서 끝내 정리된 세션도 함께 되돌림). 필터 초기화나 페이지를 다시 열면 지운 세션 포함은 꺼집니다. 보드 터미널이 열린 세션은 **(실행 종료·연결 닫기) 뒤 목록에서 지우기**로 터미널을 닫고 지울 수 있으며, 닫기가 확인된 뒤에만 지웁니다. 실행과 대화 기록은 건드리지 않습니다.
- 답 필요·최근 끝남 묶음에서 마지막으로 연 뒤에 바뀐 세션에는 파란 점을 표시합니다. 읽음 기록은 보드 상태 폴더(`session-seen.json`)에 저장돼 모든 기기에서 같고, 처음 연 시점 이전에 바뀐 세션은 읽은 것으로 봅니다. 대화를 열거나, 연 채로 그 세션이 답을 기다리거나 끝나면 읽은 것으로 기록합니다.
- 대화 입력창의 도구 › 빠른 답장은 설정에 적은 문구(한 줄 200자, 12개까지)를 선택하면 입력창의 커서 위치에 넣고 바로 전송합니다. 기존 초안과 첨부도 함께 전송되며, 목록을 열거나 닫기만 하면 전송하지 않습니다. 문구를 보드에 저장하면 모든 기기에서 공유합니다. 처음 저장하기 전에는 기존 브라우저 문구를 유지합니다. 다른 기기에서 먼저 저장한 수정과 충돌하면 편집 내용을 보존하고 최신 문구를 확인하게 합니다. 저장 실패를 완료로 표시하지 않으며 이 기기 저장이 실패한 문구는 현재 화면에서 사용할 수 있습니다. 집중 모드(도구가 접힌 상태)에서는 보내기 옆 빠른 답장 버튼으로 같은 목록을 엽니다. 전송 불가·진행·결과 미확인 상태와 한글 조합 중에는 꺼집니다.
- 응답 없이 멈춘 요청은 읽기 30초, 쓰기 45초(보내기 90초, 실행 11분처럼 서버가 원격 작업 뒤 답하는 요청은 그보다 길게) 뒤 실패로 처리해 다음 읽기와 연결 끊김 안내를 막지 않습니다. 배포 전에 연 화면은 새 버전이 있다고 안내하고, 보내지 않은 글·첨부·열린 터미널·열린 창이 없으면 화면으로 돌아올 때 새 화면을 불러옵니다.
- 응답 종료나 전송 접수는 목표 완료가 아닙니다. 끝남은 원본 세션이 작업을 멈췄다는 뜻이며 결과를 검증했다는 뜻이 아닙니다.

## 봇 요청과 권한 경계

- 별도 `bot-sources.json`에 등록한 원장만 읽습니다. 봇 이름·대화 제목으로 세션을 봇으로 추정하지 않습니다(봇 탭 분류는 아래의 실행 출처·실행 폴더로만 합니다). 지원 adapter는 팀 요청 수신함, Slack gateway 세션 DB, Slack 요청 원장입니다.
- 요청 상태는 원본의 접수·처리 상태입니다. 이벤트 처리 완료를 업무 목표 완료로 해석하지 않습니다. 요청자나 채널을 확인할 수 없으면 미확인으로 표시하고 권한은 원래 봇 정책의 설명으로 제공합니다.
- 대화 본문을 암호화한 원장은 키를 읽거나 복호화하지 않습니다. native 세션 ID가 명시되고 해당 계정 DB에서 확인된 경우에만 원래 세션과 연결합니다.
- 봇 요청 목록에는 일반 세션의 입력·재개·터미널·종료 버튼을 제공하지 않습니다. 확인된 봇 native 세션으로 직접 실행하는 API도 거절해 원래 봇의 승인과 사용 범위를 우회하지 않습니다. 원래 세션이 목록에 있는 요청과 봇이 연 세션은 누르면 그 대화를 보기 전용으로 보여 주고 계속 새로 고칩니다(입력창 자리에 요청자·채널·권한·상태). 봇 요청 탭에는 요청 원장에 없는 봇의 세션도 '봇이 연 세션'으로 함께 보입니다.
- 원장 조회는 소스별 최근 최대 100건, 읽기 전용·시간 제한으로 수행하고 120초간 캐시합니다. 실패한 소스는 10분 뒤(또는 사용자가 다시 확인하면) 다시 읽습니다. 원장 읽기는 한 번에 하나씩, 대화 읽기·전송·알림이 기다리는 잠금 밖에서 합니다. 대화 읽기·전송·알림 분류의 봇 세션 확인은 마지막으로 읽은 목록으로 바로 답하고, 목록이 오래됐으면 뒤에서 다시 읽습니다(처음 한 번만 읽기를 기다림).
- 대화가 남아 있는 요청은 열면 요청 정보 아래에 그 대화를 보기 전용으로 보여 줍니다. Hermes 세션은 봇의 Hermes DB(Slack gateway 세션 DB는 그 DB, 요청 원장은 원장 폴더 옆 `hermes/state.db`)에서 사용자·봇의 글만 세션마다 최근 80개까지 읽기 전용·시간 제한으로 읽고, 도구 호출·결과·추론은 읽지 않습니다. 원장이 적은 Hermes 세션 ID는 보드 서버에만 두고 화면에는 가린 별칭만 보냅니다. 토큰 같은 비밀값은 가리고 알려진 Slack 요청 봉투는 걷어 냅니다. 사용자 글은 사람이 채팅으로 입력한 말만 보입니다. Hermes 게이트웨이가 저장할 때 덧붙인 발신자 표지(`[이름 | Slack user <@…>]`), 스레드·채널의 앞선 메시지 맥락, 답장 대상 인용, 첨부 안내, 스킬 본문은 걷어 내고, 게이트웨이가 스스로 넣은 알림(`[IMPORTANT: …]`: 백그라운드 작업 완료 등)과, Hermes가 사용자 말이 없는 행으로 보는 것(`[ASYNC DELEGATION …]`, 작업 목록 보존, `Cronjob Response:` 등)은 맥락·발신자 표지 뒤에 붙어 있어도 보이지 않고, 글 앞의 시스템 메모(`[System note: …]`)는 걷어 냅니다. 대화 압축 요약(`[CONTEXT COMPACTION …]`)은 사용자·봇 어느 쪽 글이든 보이지 않으며, 요약과 합쳐진 글은 원래 글만, 요약 뒤에 이어진 글은 그 글만 보입니다(Hermes 자체 복원 규칙과 같음). 스킬을 부른 글은 입력한 대로 `/스킬 지시`로 보이고, 첨부만 보낸 글은 "(첨부 파일)"로 보입니다. 맥락이 길어 읽는 길이를 넘으면 글 끝을 따로 읽어 입력한 말을 찾습니다. 채널·토픽에 묶여 스킬이 자동으로 실릴 때(Telegram·Discord)는 그 첫 메시지가 보이지 않습니다. Codex 세션의 사용자 글에서도 Codex가 넣는 지침·환경 블록(`# AGENTS.md instructions …`, `<environment_context>`)은 보이지 않습니다(보드의 일반 Codex 대화도 같음). 대화 본문은 보드의 다른 대화처럼 주소·링크·멘션을 가리지 않으며, 요청자·채널 같은 요청 라벨만 가립니다. 목록에 없는 원래 Codex 세션은 보드의 일반 대화 읽기로 보여 줍니다. 열 때 한 번 읽고 1분 안에는 다시 읽지 않으며, 요청이 바뀌었거나 '대화 다시 불러오기'를 누르면 다시 읽습니다. 봇에 입력·전송·재개하지 않습니다.
- 봇이 같은 대화 키(요청 원장의 `session_key`, gateway 세션의 `session_key`: 한 사람과의 DM이나 한 스레드)로 둔 요청은 카드 하나로 묶고 최신 요청의 제목·상태와 요청 수를 보여 줍니다. 키 자체는 화면에 보내지 않고 가린 별칭만 보냅니다. 열면 묶인 요청들이 거친 세션(Codex·Hermes)의 대화를 첫 요청 시각 순으로 이어 붙이고 세션 사이에 구분선을 둡니다. 최근 100건 안의 요청만 묶고, 세션은 최근 6개까지 읽습니다. Codex 세션 하나뿐인 대화는 지금처럼 그 세션을 바로 엽니다. 키가 없는 요청은 요청마다 카드입니다.

## 닫힌 세션 재개

- 기기 오프라인과 세션 종료를 구분합니다. 연결을 확인한 뒤 같은 Codex UUID·계정 홈·작업 폴더를 다시 검증하고 사용자가 누른 경우에만 터미널을 엽니다. 메시지·새 모델 turn을 자동으로 보내지 않습니다.
- 웹보드에서 명시적으로 종료하거나 터미널을 닫은 기록은 재개와 구분합니다. 연결 끊김으로 터미널이 사라진 경우에는 사용자 종료로 기록하지 않습니다. 구버전의 원인 없는 닫힘 기록으로 사용자 종료를 추정하지 않습니다.
- 원본이 보관됐거나 계정·작업 폴더가 맞지 않으면 자동 보관 해제나 다른 계정으로 대체하지 않습니다.

## 세션 중단·종료·보관

- 세션 관리에서 현재 원본의 지원 여부를 확인합니다. **응답 중단**은 진행 중인 turn을 멈추고, **실행 종료**는 확인된 native 실행을 끝내며, **보관**은 보드의 작업을 숨깁니다. 보관은 실행을 멈추거나 원본 기록을 삭제하지 않습니다.
- Codex 응답 중단은 app-server가 확인한 해당 turn만 대상으로 합니다. CLI 실행 종료는 정확한 계정 홈·세션·원본 프로세스를 입증할 수 있을 때 지원합니다. 앱 서버의 세션은 정확한 저장 기록을 확인한 뒤 native thread/archive로 종료·보관할 수 있습니다. 하위 에이전트도 보관을 요청하므로 확인창에 그 범위를 표시하며, 종료 확정은 선택한 세션의 미로드 상태와 보관 기록으로 판단합니다. 공용 daemon 자체를 종료하지 않으며 식별이 불충분하면 이유를 표시합니다.
- Claude의 응답만 중단하는 공식 제어는 현재 지원하지 않습니다. 확인된 백그라운드 실행 또는 정확하게 식별한 native CLI는 실행 종료를 사용할 수 있습니다. 원본을 확인할 수 없거나 이미 끝난 세션이면 실행하지 않습니다.
- 미리보기 후 원본 turn·프로세스가 바뀌면 제어를 거절합니다. 결과가 유실되거나 원본 종료를 확인하지 못하면 미확인으로 남기며 자동 재전송·강제 종료하지 않습니다. 이 기능의 합성 검증은 실제 계정·모든 CLI 버전·원격 프로세스 제어 검증을 대신하지 않습니다.

## 세션 조회와 연결

- 웹보드의 세션 제목은 보드에서 표시할 이름으로 따로 저장합니다. 기기·에이전트·계정 홈·세션 ID가 모두 같은 세션에만 적용하며 원본 CLI의 제목이나 대화 기록을 바꾸지 않습니다. 일반·에이전트 세션에서 수정하고 원래 제목으로 되돌릴 수 있으며, 봇 요청의 제목은 원래 봇의 기록을 따릅니다.
- 세션 목록은 프로젝트·제목·기기·세션 상태를 구분해 보여줍니다. 프로젝트명은 호스트 설정의 라벨이나 기록된 작업 폴더 이름을 사용하고, 짧은 폴더 힌트로 작업 위치를 구분합니다. 별도로 수정하지 않은 제목과 대화 미리보기는 원본 CLI의 값을 사용하므로 현재 작업 내용과 갱신 시점이 다를 수 있습니다.
- 수집기는 설치된 CLI의 로컬 세션 정보를 읽습니다. 세션 형식이나 CLI 동작이 바뀌면 조회·재연결이 제한될 수 있습니다. 오프라인 호스트에서는 마지막으로 저장한 결과가 보일 수 있으며, 오래된 값은 현재 상태로 간주하면 안 됩니다.
- 세션 목록은 **일반 세션 / 에이전트 세션 / 봇 요청**으로 나누고 일반 세션을 기본으로 엽니다. 일반 세션은 직접 시작한 세션만, 에이전트 세션은 하위 에이전트·프로그램 실행·출처 미확인 세션을, 봇 요청은 봇 요청과 봇이 연 세션을 보입니다. 검색·상태·기기 필터는 선택한 목록에 적용하며 다른 목록의 검색 결과로 이동할 수 있습니다.
- 시작 주체는 직접 시작·에이전트·프로그램 시작·출처 미확인이며, 세션을 연 방식으로 구분합니다. 명시 initiator가 있으면 그것을 따르고, 하위 에이전트(Codex subagent 구조, 부모 세션 참조)는 에이전트입니다. 그 밖에는 Codex가 기록한 실행 방식(`source`)이 `cli`(터미널 UI)·`vscode`(앱·IDE 연결)이면, 기록이 없을 때는 `originator`가 터미널 UI(`codex-tui`)나 보드 실행(`session-board`)이면, Claude는 interactive·background 세션이면 직접 시작으로 봅니다. `exec` 실행과 기록 없는 다른 originator(`codex_exec` 등)는 프로그램 실행입니다. originator는 마지막에 붙은 클라이언트(보드의 읽기 도구 등)일 수 있어 실행 방식보다 뒤에 봅니다. 실행 방식에서 추정한 것이라, 사람이 연 터미널 UI에 에이전트가 입력했거나 프로그램이 터미널 UI를 띄운 경우는 직접 시작으로 보일 수 있습니다. 봇 요청에 묶인 세션, Codex `originator`가 `hermes`인 세션, 봇의 작업 폴더(경로에 `workspaces/slack` 또는 `.hermes`)에서 실행된 세션은 봇이 연 세션입니다. 현재 워커의 이름과 역할은 시작한 주체와 별도입니다. 시작 주체 필터는 세션을 연 봇(봇 요청 출처의 이름, "이름 · 채널" 꼴은 이름만; Codex `originator`가 `hermes`이면 헤르메스)으로도 고를 수 있고, 고르면 그 봇이 연 세션을 탭과 상관없이 지금 탭에 보여 주며(봇 요청에 묶인 세션 포함), 그 세션을 열어도 탭과 필터가 그대로입니다. 카드에는 '(봇 이름) 시작'으로 표시합니다.
- Windows Claude는 살아 있는 정확한 PID·생성 시각·허용 실행파일과 부모 계보를 검증한 경우에도 에이전트 시작으로 구분합니다. 제목에 리뷰가 있거나 print 모드라는 이유만으로 분류하지 않습니다. 조회 시 이미 부모가 종료됐거나 근거를 확인할 수 없으면 출처 미확인으로 남을 수 있습니다. `claude --bg` 세션은 Claude 데몬이 띄운 Claude 자체 PTY 호스트(`--bg-pty-host`) 아래에서 돌아 원래 호출자가 계보에 없으므로, PTY 호스트는 에이전트 근거로 보지 않습니다. 그래서 백그라운드 세션은 직접 시작으로 보이며, 에이전트가 연 백그라운드 세션도 일반 세션에 보일 수 있습니다.
- PC에서 실행 중인 Claude background 세션은 소유 프로세스를 검증한 실행 기록의 job id로 보드 터미널에서 `claude attach`합니다(`claude attach`는 세션 UUID를 받지 않습니다). 기록에 job id가 없는 이전 버전 실행은 원본 PC 터미널에서 이어가야 합니다. 보드 연결은 SSH 로그온 세션에서 실행되므로, 다른 Windows 로그온 세션(콘솔 등)에서 시작한 background 세션에 붙는지는 실제로 확인하지 않았습니다.
- Windows의 일회성 Claude 실행은 명시된 실행 옵션을 확인해 표시합니다. 대화 저장을 끈 실행은 오류 대신 기록 미저장 사유와 실행 상태를 보여 주며 세션 관리를 유지합니다. 후속 메시지·터미널 재개는 제공하지 않으며, 결과는 실행을 요청한 에이전트에서 확인해야 합니다. 저장되지 않은 대화를 복원하지 않으며, 실행 옵션을 확인하지 못한 경우 일반 대화 읽기 오류와 구분할 수 없습니다.
- 실제 수집 adapter는 Codex와 Claude Code입니다. Codex의 구조화 subagent source와 Claude 목록이 제공하는 명시 시작·부모 정보는 전달하지만 Hermes나 모든 자동 실행 기록을 수집하지는 않습니다. 앱 서버가 없는 Codex home은 DB에서 보관되지 않은 모든 source의 최신 25개를 읽습니다. 구버전 daemon이 source 필터를 거절하면 대화형 세션만 표시될 수 있다는 경고를 남깁니다.
- 연결에 실패한 기기는 화면이 열려 있는 동안 점점 길게(약 1분 30초·3분·5분, 이후 5분마다) 기다린 뒤 다음 화면 갱신 때 자동으로 다시 확인합니다. 그 사이에는 반복 접속하지 않으며, 새로고침 버튼은 즉시 다시 확인합니다.
- 같은 탭에서 다시 연 대화는 메모리에 남은 내용을 먼저 보여주고 최신 기록을 확인합니다. 확인 중이거나 연결이 끊긴 경우 이를 표시하며, 기기·계정·세션·작업 폴더가 다르면 이 내용을 재사용하지 않습니다. 잠금이나 인증 만료 시 메모리의 대화도 지웁니다. 읽은 대화 내용은 최근에 연 대화 12개까지만 메모리에 남기고, 그보다 오래된 대화는 다시 열 때 새로 읽습니다(이때는 저장된 내용을 먼저 보여 주지 않습니다). 초안·첨부가 있거나 전송·업로드·상태 확인이 진행 중인 대화와 화면에 열린 대화는 이 수에 먼저 포함되며 비우지 않습니다. 봇 요청 대화도 최근에 읽은 12개까지만 남깁니다.
- Codex 연결은 확인된 로컬 daemon 세션과 정확한 세션 식별자를 사용합니다. vendor의 cloud Remote 세션, 불명확한 ID, 또는 필요한 daemon 연결이 없는 세션을 임의로 재개하지 않습니다.
- Claude background 세션은 exact attach를 지원합니다. 기존 interactive 세션의 직접 attach는 지원하지 않으며 native 터미널을 사용해야 합니다.
- 계정 전환과 새 세션 생성은 대상 호스트에 이미 준비되어 있는 계정을 사용합니다. 로그인 자격증명이나 provider 설정을 다른 호스트로 복사하지 않습니다.
- 버전 2의 `profiles[].launchEnabled` 또는 `profileRules[].launchEnabled`를 `false`로 두면 프로필과 기록은 남기고 보드의 새 CLI 실행·앱 서버 시작을 거부합니다. 라우터 계정 정책의 중단 계정도 실행하지 않습니다. `hide`는 수집도 숨기고 `excludeSuspended`는 중단 계정 수집을 제외하는 별도 설정입니다. 임의 `launcher.command` 내부의 계정 선택·실행 정책은 그 실행 명령이 담당합니다.
- 보드의 새 세션 터미널과 나중에 나타난 native 대화를 시각으로 짝짓는 연결은 `estimated`이며 정확한 매핑이 아닙니다. 같은 기기에서 거의 동시에 시작된 다른 대화를 가리킬 수 있습니다. 이를 native 대화의 직접 시작 증거나 목표 자동 연결 근거로 사용하지 않습니다. 외부 실행 기록의 launch ID와 보드 요청을 정확하게 연결하는 계약은 아직 지원하지 않습니다.

## 메시지와 첨부

- 에이전트 답변은 기본 Markdown 서식(제목·문단·목록·인용·강조·코드·HTTP(S) 링크)으로 표시합니다. 목록 항목은 들여쓴 이어지는 줄, 빈 줄로 띄운 항목·하위 항목, 들여쓴 코드 펜스를 같은 항목으로 묶습니다. 문단 중간의 번호 줄은 `1.`로 시작할 때만 목록이 되고, `2026. 10. 10.` 같은 날짜 줄은 목록으로 보지 않습니다. 코드 블록은 위쪽 머리 줄에 언어와 복사 버튼을 둡니다. 본문 복사는 인용·강조 기호를 제거하고 링크 주소를 남기며, 코드 복사는 문자·들여쓰기·줄바꿈을 보존합니다. 사용자 입력과 native 대화 원문은 수정하지 않습니다.
- 기본 대화 표시는 메시지당 4,000자입니다. 긴 메시지의 **전체 보기**는 같은 원본 본문 해시를 저장 기록에서 찾아 65,536자씩 불러옵니다. 추가 내용은 **다음 부분 불러오기**로 이어 읽으며, 모두 불러오기 전에는 복사를 표시된 부분으로 구분합니다. 원본 대화는 바꾸지 않습니다. 저장 기록의 계정·세션 신원을 확인하지 못하면 기존 표시를 유지합니다. 한 화면의 펼친 본문은 2MiB까지이며 8MiB를 넘는 JSONL 한 줄, 기록 미저장 실행과 삭제된 원본은 이 경로로 읽지 못할 수 있습니다.
- 목록 검색 옆 **본문**을 켜고 검색을 실행하면 현재 목록에 등록된 세션들의 저장 대화를 검색합니다. 최근 80개 표시 범위 밖의 메시지도 읽으며 기기·파일별로 이어서 검색하고 진행·실패 범위를 표시합니다. 지운 세션은 **지운 세션 포함**을 켠 경우에만 포함합니다. 결과를 고르면 같은 대화에 **검색한 메시지 · 저장 기록**으로 원문을 보여 주며 최근 대화와 입력 상태를 바꾸지 않습니다. 기기 연결과 저장 원장이 필요하고 한 번에 결과 500개까지 표시합니다. 목록에 수집되지 않은 세션 전체를 별도 색인하는 기능은 포함하지 않습니다.

Claude 백그라운드 세션은 답을 낸 뒤에도 도구·하위 작업이 남으면 계속 작업 중이기 때문입니다. 세션 상태는 입력창 위 상태 문구와 목록 배지에 표시하며, 열어 둔 대화의 상태 확인이 목록보다 새로우면 그 대화의 카드·머리말·상단 개수가 목록 수집을 기다리지 않고 따라갑니다(목록의 상태가 바뀌면 다시 목록 기준). 아직 읽은 기록이 없으면(ID 없는 Claude 세션 등) 세션 상태만으로 표시합니다.

Claude Code는 붙여넣은 이미지 경로를 `[Image #1]` 표시와 이미지로 바꿔 기록하고 `첨부 파일:` 줄을 지우므로, 비교할 때 `[Image #N]`·`[Pasted text #N +M lines]` 같은 입력 표시와 첨부 줄을 빼고 봅니다(이미지 칩이 있는 사용자 말풍선에서는 `[Image #N]`도 그리지 않습니다). 작업 중에 보낸 Claude 메시지는 Claude Code가 대기 입력(`queued_command`)으로만 기록하는 경우가 많아, 사람이 입력한 대기 입력도 사용자 메시지로 보여 줍니다. 중단(Esc)으로 같은 입력이 다시 기록되면 한 번만 보입니다. 보조 판정으로, 서버가 접수를 확인한 Claude 말풍선은 문장을 맞추지 못해도 보낸 뒤 들어온 짝 없는 사용자 메시지와 순서대로 1:1로 짝짓고, 서버가 기록 반영을 확인했거나 보낸 뒤 에이전트 답이 기록됐으면(작업 중이면 1분 뒤부터) 정리합니다. 그래서 다른 곳에서 거의 같은 때 입력한 메시지와 짝이 바뀌어 말풍선이 조금 일찍 사라질 수 있습니다. Codex 말풍선은 요청 ID로만 짝짓습니다(서버가 기록 반영을 확인하면 Codex 말풍선도 정리합니다). 말풍선이 정리되면 입력창 위 "메시지를 접수했습니다" 안내와 전송 첨부 표시도 함께 사라집니다.

Claude 대화는 그 기기의 상주 수집기가 목록을 보내는 동안 목록에 있는 상태(작업 중·답 필요 등)를 그대로 쓰고 읽을 때마다 `claude agents`를 실행하지 않습니다. 상주 수집기는 Claude 세션 상태가 바뀌면 1~2초 안에 목록을 다시 보내므로, 대화 화면의 상태 표시가 실제보다 1~3초 늦을 수 있습니다(대화 내용은 읽을 때 기록 파일에서 읽어 늦지 않음). 상주 수집기 없이 1분 이상 간격으로 수집하는 기기, 대화 기록 파일을 찾지 못한 경우, 보내기·첨부 올리기의 확인은 지금처럼 `claude agents`로 확인합니다.
- 2초를 넘긴 대화 보내기는 보드 기록(stderr)에 단계별 소요 시간을 한 줄 남깁니다(`느린 전송 claude 4.82s prepare=… lock=… capabilities=… terminal=… open=… screen=… paste=… submit=… save=… rest=…`). 에이전트 종류와 초만 남기고 메시지·제목·세션 ID·기기 이름은 남기지 않습니다.
- Claude CLI에는 기존 세션에 메시지만 보내는 명령이 없어, 보드가 그 세션에 연결한 tmux 터미널에 붙여넣고 Enter를 보냅니다. 백그라운드 세션에 보드 터미널이 없으면 **보내기**를 누를 때 보드가 그 세션에 `claude attach` 연결을 먼저 열고 이어서 보냅니다. 연결을 열지 못하면 아무것도 붙여넣기 전이므로 보내지 않은 것으로 확정하고 이유와 초안을 남깁니다. **답 필요** 묶음의 카드나 알림으로 Claude 백그라운드 세션을 열면 질문 카드의 "질문 불러오기"를 한 번 자동으로 실행해 선택지를 바로 보여 줍니다. 보드 밖 터미널 앱에서 직접 실행 중인 Claude 세션은 웹에서 입력할 수 없습니다. 터미널 화면에 승인·질문 선택 메뉴(`❯ 1.` 형식)가 떠 있으면 입력이 메뉴 선택으로 처리될 수 있어 보내지 않습니다. 같은 요청은 다시 붙여넣지 않으며, 본문 대신 앞부분의 해시(붙여넣은 그대로, 그리고 입력 표시·첨부 줄을 뺀 문장)만 보관해 대화 기록에서 반영 여부를 확인합니다. 붙여넣기 결과를 받지 못해 "결과 미확인"이던 요청도 대화 기록에서 그 메시지가 확인되면 접수로 바뀌어 전송 잠금이 풀립니다(다시 보내지는 않습니다).
- 그 연결이 없는 Claude 백그라운드 대화에 입력을 시작하면(타이핑·마이크·빠른 답장) 보드가 그 세션의 `claude attach` 연결을 미리 엽니다(대화마다 1분에 한 번). 그래서 보내기는 연결을 기다리지 않고 바로 붙여넣으며, 카드에는 입력을 시작할 때부터 '터미널 열림'이 보입니다. 아무것도 입력하지 않고, 보내지 않으면 다른 유휴 연결처럼 그 대화를 보고 있지 않을 때 10분 뒤 닫힙니다. 끝난(done) 세션, 보드 터미널이 15개 이상일 때, 다른 미리 열기가 진행 중일 때는 미리 열지 않습니다. 연결이 준비됐는지는 화면이 잠시 멈추거나, 작업 중인 세션처럼 계속 그려지면 맨 아래의 입력 줄(위아래 구분선 사이의 `❯`/`>`, 0.5초 간격 두 번 연속)로 판단합니다.
- 승인·질문 메뉴는 보드가 그 세션에 연결한 터미널 화면에서 읽어 대화 화면의 질문 카드로 보여 줍니다. 선택지를 고른 뒤 보내기를 따로 눌러야 하고, 보내기 직전에 화면을 다시 읽어 같은 메뉴일 때만 방향키와 Enter를 입력합니다. 여러 개를 고르는 메뉴, 현재 선택 위치를 알 수 없는 메뉴, 보드 밖 터미널에서 실행 중인 세션은 터미널에서 답해야 합니다. 화면 형식은 CLI 버전에 따라 달라질 수 있습니다. 같은 세션의 보드 터미널로 돌아갈 때는 확인 창 없이 바로 연결합니다.
- 결과가 불명확한 메시지는 자동으로 다시 보내지 않습니다. 수신 여부를 먼저 확인하고, 같은 요청을 반복 제출하지 마세요.
- 서버가 native 전송 전 거절을 확인한 경우에는 초안과 첨부를 남기고 입력 잠금을 해제합니다. HTTP 오류 번호만으로 미전송을 추정하지 않습니다. 잠그기와 인증 만료는 대화·초안을 지우는 별도 보안 동작입니다.
- 텍스트는 메시지당 UTF-8 32 KiB, 첨부 파일은 개별 20 MiB, 메시지당 8개까지입니다. 첨부 파일은 실제 세션의 작업 폴더 아래 보드 관리 디렉터리(`.sessionholic-attachments/`)에 저장됩니다. 작업 폴더가 Git 저장소 안이면 이 디렉터리를 저장소의 `info/exclude`에 한 번 추가해 `git add -A`에 포함되지 않게 합니다. 이 처리는 최선 노력이라 실패해도 업로드는 진행되며, 이미 추적 중이거나 강제로 추가한 파일은 막지 않습니다. 보통 파일은 내용 전체를 메시지에 삽입하는 대신 native CLI가 읽을 수 있는 경로로 전달합니다.

## 인계와 기기 간 이전

- 같은 native 세션에 연결하는 경우 기존 프로세스를 사용합니다. 도구·계정 변경을 위한 인계는 최근 대화와 Git 상태 등의 맥락을 전달해 **새 native CLI 세션**을 실행합니다. 원본 프로세스, 실행 중인 turn, 승인 상태를 새 호스트로 옮기는 기능이 아닙니다.
- 원격 기기 안의 도구·계정 전환도 같은 의미의 인계입니다. 같은 작업 폴더에서 대상 에이전트를 새로 열고 원본 대화는 그대로 둡니다. 인계 문서·Codex app-server·실행 환경 경계·환경 변수는 모두 그 원격 기기 기준입니다. 보드의 실행 계획은 경로 이름만으로 경계를 추정하고, 실제 판정은 실행 직전에 원격 helper가 그 기기의 설정으로 다시 합니다. 추정과 실제 판정이 다르면 실행하지 않습니다. 원격 기기 연결이 끊겼거나 원본이 작업 중·승인 대기면 실행하지 않습니다. Codex 대상은 그 기기의 대상 계정 app-server 연결이 있어야 합니다.
- 원격 인계 준비 응답이 유실되면 첫 지시가 이미 전달됐을 수 있습니다. 보드는 결과를 미확인으로 알리고 자동으로 다시 실행하지 않습니다. 원격 기기의 작업 목록을 먼저 확인하세요.
- 원격 helper는 실행하지 않고 만들어질 명령의 요약만 보여 주는 점검 모드를 제공합니다. `python3 -I <helper.pyz> handoff --check -`에 요청 JSON(`{"source": {"agent", "id", "home", "cwd", "phase"}, "target": {"agent", "account"}}`)을 표준 입력으로 주면 대상 프로필·경계·실행 파일을 확인하고, 실행 파일 이름·작업 폴더·환경 변수 키 목록(값 제외)만 출력합니다. 첫 지시를 보내거나 파일을 남기지 않습니다. 보드가 준비한 요청은 `handoff --check <요청 해시>`로 실행 전 내용을 같은 형식으로 확인할 수 있습니다.
- 원격 helper(`worker-<SHA>.pyz`)는 처음 쓸 때 해시를 확인한 바이트로 같은 이름의 폴더(`worker-<SHA>/`, 소유자 전용)에 한 번 풀고, 이후 호출은 그 폴더에서 실행해 컴파일한 모듈(`__pycache__`)을 다시 씁니다. macOS 기본 `python3`는 바이트코드를 기록하지 않지만 이 폴더에서만 기록을 켭니다. `.pyz`는 그 폴더에 기록한 inode·크기·수정 시각이 바뀔 때만 다시 해시하고, 사용 표시(수정 시각)는 한 시간에 한 번만 갱신합니다. 같은 사용자가 폴더나 파일을 바꾸는 것은 막지 않습니다(`.pyz`와 같은 신뢰 경계). 폴더를 준비하지 못하면 이전처럼 `.pyz`에서 실행하고, 터미널 단계는 계속 `.pyz`를 실행합니다. 다른 버전의 폴더는 그 `.pyz`가 정리될 때(하루 미사용) 함께 지웁니다.
- 기기의 계정 목록과 새 세션 가능 여부는 2분간 캐시합니다. 2분이 지나면 화면 요청은 마지막 목록으로 바로 답하고 그 기기에는 뒤에서 한 번만 다시 묻습니다. 최근 읽기가 실패했으면(2분 안) 그 실패를 보여 줍니다. 실행 계획·이전·새 세션 열기는 그 요청 안에서 다시 읽은 목록으로 판단합니다.
- 기기 간 이전은 원본 응답을 확인하고 중단한 뒤 선택된 작업공간 파일과 최근 대화를 새 목적 폴더로 복사하고 대상 호스트에서 새 세션을 준비합니다. 원본 파일과 기록은 남겨 둡니다. 이는 프로세스 이동이나 완전한 복원 기능이 아닙니다.
- 작업공간 아카이브는 최대 128 MiB, 파일 항목은 최대 20,000개입니다. Git 저장소에서는 Git이 무시하는 폴더와 중첩 저장소·worktree를 세지 않고 복사하지 않습니다. Git이 아닌 폴더에서는 빌드 결과물·의존성·도구 캐시 폴더(`node_modules`, `Pods`, `.gradle`, Cargo·Maven `target` 등)를 제외합니다.
- 이전은 알려진 자격증명과 특수 파일을 제외하고 제한된 크기의 작업공간을 복사합니다. 인증 파일(`.env`, `auth.json`, 개인키, `.ssh` 등)과 프로젝트 `.claude`·`.codex` 폴더의 개인 설정·세션 기록은 복사하지 않고, 공유 설정(`agents`, `commands`, `skills`, `hooks`, `settings.json`, `AGENTS.md`)은 복사합니다. 이름이 자격증명처럼 보이는 미추적 파일(`token`·`secret`·`credential`이 들어간 데이터 파일, `secrets/`, `*.key`, `.envrc`, `*.tfvars` 등)은 제외하고 미리보기에 목록과 경고를 표시합니다. 두 종류 모두 Git이 추적하거나 HEAD 이력에 있으면 번들 이력에 포함되므로 이전 전체를 거절합니다.
- 제외 규칙이 모든 비밀정보를 식별한다고 보장할 수 없습니다. 미리보기의 큰 파일·제외 파일 목록과 경고를 검토하고, 민감한 정보가 없는지 확인하세요.
- 원본이 이전 중 다시 변경되거나 대상이 준비되지 않으면 새 세션 실행을 중단합니다. 이미 중단된 원본 응답은 자동으로 재개하지 않습니다.
- 대상 준비 요청의 응답이 유실되면 이미 대상 작업이 시작됐을 수 있습니다. 보드는 결과를 미확인 상태로 기록하고 같은 요청을 자동 재실행하지 않습니다. 대상 기기의 작업 목록과 이전 기록을 확인한 뒤 다음 작업을 진행하세요. 대상 도우미가 새 세션 연결 전 단계(검증·파일 복원·실행 준비)에서 실패를 직접 보고한 경우에는 그 원인을 실패로 기록하고 대상 임시 파일을 정리합니다.
- 터미널 연결 자리는 대상 실행 준비 전에 확보합니다. 이후 연결 자체가 실패할 수 있으며, 이때는 대상 기기와 준비된 세션 정보를 안내합니다. 새 인계 계획을 명시적으로 실행하면 별도 작업이 만들어질 수 있으므로 먼저 대상 목록을 확인하세요. 모든 단계의 자동 복구를 제공하는 것은 아닙니다.

## 즐겨찾기와 채팅 명령

- 목록 메뉴나 대화의 **상단 고정**으로 즐겨찾기에 넣습니다. 고정은 보드에 저장되어 기기끼리 공유하며, 오래된 대화도 목록 맨 위에 한 번만 표시합니다. 검색·기기·분류 조건과 명시적인 **목록에서 지우기**는 고정한 대화에도 적용됩니다. 원본 에이전트의 제목·세션은 바꾸지 않습니다.
- 채팅 입력창의 `/`는 `/model`, `/effort`, `/compact`, `/clear`를 제안합니다. 위·아래 화살표로 고르고 Enter·Tab으로 완성하며, 선택 자체로 명령을 실행하지 않습니다. 입력한 명령은 보내기 버튼이나 전송 단축키로 실행합니다. 모델·에포트는 제목 옆 표시를 눌러서도 고를 수 있습니다. 명령에는 첨부를 넣을 수 없으며, 지원하지 않는 슬래시 명령을 일반 모델 메시지로 보내지 않습니다.
- Codex 모델 목록과 지원 에포트는 해당 계정의 native `model/list`에서 읽습니다. 선택은 그 기기에 저장하며 다음 **대기 상태의 웹 입력**에 `turn/start`의 모델·에포트로 넘깁니다. 진행 중인 turn에 합류하는 입력은 현재 설정을 유지합니다. 제목 옆 화살표 앞은 native에서 읽은 현재 값, 뒤는 다음 웹 입력 설정입니다. 원본 터미널의 입력에는 아직 적용되지 않은 보드 선택을 강제하지 않습니다. [Codex 공식 app-server 프로토콜](https://learn.chatgpt.com/docs/app-server)을 따릅니다.
- Claude는 보드가 연결한 터미널에 native `/model`·`/effort` 명령을 전달합니다. 모델·에포트의 완료 표시는 CLI 확인 문구나 입력창 아래 상태 표시에서 확인한 값만 사용합니다. 확인 전에는 전달 상태를 표시하고, 마지막 응답에서만 알 수 있는 모델은 그렇게 설명합니다. 에포트를 확인하지 못하면 **미확인**으로 표시합니다. 승인 메뉴·입력 중인 문장·작업 중·다시 연결 중에는 명령을 전달하지 않습니다. 모델에 따라 에포트 선택지를 CLI가 거절할 수 있습니다. [Claude Code 명령](https://code.claude.com/docs/en/commands)을 사용합니다.
- `/compact`는 현재 대화의 native 요약을 시작하며 완료까지 기다렸다고 표시하지 않습니다. 결과를 못 받으면 같은 명령을 자동으로 재실행하지 않습니다. Claude가 Enter를 줄바꿈으로 받았을 때에는 정확한 명령이 입력창에 남아 있는 것을 확인한 경우에만 Enter를 한 번 더 누릅니다. `/clear`는 기존 기록을 보존하고 **새 세션** 선택 창을 엽니다. 새 세션의 기기·에이전트 선택은 해당 실행 설정을 따릅니다.

## 알림

- 알림 분류는 목록과 같은 순서로 봇·부모 세션·역할·실행 출처를 확인합니다. 알림 대기 항목과 마지막 관측 상태를 함께 저장해 보드가 재시작되어도 아직 표시하지 못한 알림을 유지합니다. 새 알림 처리기는 읽기만으로 대기 항목을 지우지 않으며, 실제로 표시한 알림의 고유 식별자만 확인 처리합니다. 표시·확인 응답이 실패하면 최대 1시간 동안 다시 전달을 시도하고, 이미 같은 알림이 떠 있으면 다시 소리 내지 않습니다. 이전 알림 처리기는 읽을 때 대기 항목을 소비하므로 새 처리기로 갱신해야 이 동작을 사용합니다.

- 설정의 **알림**에서 기기마다 켜고 끕니다. 아이폰·아이패드는 Safari에서 홈 화면에 추가한 앱(iOS 16.4 이상)으로 열었을 때만 켤 수 있습니다. 브라우저가 알림을 막았거나 지원하지 않으면 이유를 표시하고 켜지 않습니다.
- 일반 세션이 답을 기다리기 시작할 때와, 2분 넘게 작업한(시작부터 기록의 마지막 갱신까지) 세션이 멈출 때만 알립니다. 두 번의 수집 사이에 시작해 처음 보일 때부터 답을 기다리는 세션도 알리지만, 보드가 시작된 뒤 그 기기를 처음 읽을 때는 기준으로만 기록합니다. 에이전트가 시작한 세션·봇 요청·일회성 실행·Codex `exec` 실행·30분 넘게 갱신되지 않은 기록은 알리지 않고, 실행 상태를 확인하지 못한 기록은 마지막으로 알던 상태를 유지합니다. 마지막 상태를 저장해 재시작 뒤 같은 알림을 반복하지 않습니다. 실패 신호는 아직 원본 상태에 없어 따로 알리지 않습니다.
- 보드는 서명한 빈 알림 신호만 푸시 서비스로 보내고, 보여 줄 제목·문장은 기기의 알림 처리기가 이 보드에서 직접 읽습니다. 대화 내용은 Apple·Google 등의 푸시 서비스로 가지 않습니다. 그 대신 기기가 보드에 닿지 않거나 로그인이 끝났으면 "확인할 세션이 있어요"만 표시합니다. 알림을 누르면 해당 세션을 엽니다. 알림에는 세션 제목과 마지막 응답 앞부분이 들어가므로, 잠금 화면에 보이지 않게 하려면 기기의 알림 미리보기 설정을 바꿔 주세요.
- 알림을 보낼 때마다 건수와 전달된 기기 수를 보드 기록에 한 줄 남깁니다. 대화를 열어 둔 화면이 있어도 알림은 보냅니다(연결이 조용히 끊긴 화면을 보고 있는 것으로 잘못 알아 알림을 놓치지 않도록).
- 알림을 받는 기기가 하나라도 있으면 화면이 닫혀 있어도 보드 수집 간격마다 기기 목록을 새로 읽습니다. 받는 기기가 없으면 화면 밖에서 수집하지 않습니다. `--no-push`로 실행하면 알림과 화면 밖 수집을 모두 끄고, 설정 화면은 알림을 켤 수 없는 이유를 표시합니다.
- 브라우저가 알려 준 주소 가운데 알려진 푸시 서비스(Apple·Google·Mozilla·Microsoft)의 HTTPS 주소만 받습니다. 푸시 서비스로 가는 요청은 리다이렉트를 따라가지 않습니다. 푸시 서비스가 주소를 없앴다고 답하면(404·410) 그 기기 등록을 지우고, 요청 제한(429)·네트워크 오류·5xx면 알림을 남겨 둔 채 잠시 뒤 다시 깨웁니다. 보드 등록이 사라진 기기는 설정에서 **알림 다시 켜기**를 표시합니다.

## 터미널 입력과 상태 기록

- 종료한 전체 화면 터미널과 그 대화 화면은 뒤로·앞으로 가기로 다시 열리지 않습니다. PC에서 나란히 보기로 목록과 대화를 반복해 오가도 같은 목록 기록을 중복으로 쌓지 않습니다. 다른 터미널로 전환한 뒤 늦게 도착한 크기 변경 결과는 현재 터미널에 반영하지 않습니다.
- 입력창에 모바일 키보드가 열린 상태에서 빠른 답장을 누르면 입력창 옆 선택지를 보여 주고 입력 포커스를 유지합니다. 문구를 선택하면 입력창에 넣고 바로 전송합니다. 키보드 여닫힘은 실제 브라우저·기기에서도 확인해야 합니다.
- 오래된 세션을 목록에 복원하면 오래된 기록 필터를 함께 켜서 복원 직후 세션을 볼 수 있습니다. 연결이 거절된 안전한 Codex 앱 서버 소켓은 종료된 것으로 확인해 저장된 대화 목록을 읽습니다. 연결 상태를 확정할 수 없는 오류나 안전하지 않은 경로에서는 종료로 판단하지 않습니다.
- 상단 기기 표시에는 하드웨어만 확인하는 기기도 포함합니다. 표시 상태는 실제 확인 결과를 사용하며, 이전 값·연결 끊김·확인 중을 연결됨으로 표시하지 않습니다.

- PC·패드·폰 모두 집중 모드 버튼으로 대화 도구를 접고 복원합니다. PC 본문 클릭은 집중 모드를 전환하지 않습니다. 패드·폰은 대화의 일반 영역을 짧게 탭해도 전환하며, 버튼·링크·코드·첨부·이미지·질문 카드·텍스트 선택·길게 누르기·드래그는 제외합니다. 직접 스크롤하면 부가 도구가 접히고 맨 아래 도달·맨 아래 버튼·새 답변·질문·전송 오류가 숨김 선택을 바꾸지 않습니다. 질문과 전송 오류는 대화·입력창 곁에 표시하고, 짧은 제목·기기·복원·뒤로 가기·최소 입력은 남습니다.
- 화면 높이는 크기가 바뀔 때마다, 그리고 화면이 다시 보일 때(백그라운드·최소화·앱 전환에서 돌아올 때) 바로·다음 프레임·0.25초·1초 뒤에 다시 잽니다. iPadOS는 돌아온 직후 화면 높이를 잠깐 작게 알려 주고 그 뒤 크기 변경 알림을 보내지 않을 때가 있어, 입력 중이 아니고 확대하지 않았으면 창 높이보다 작은 값은 쓰지 않습니다.
- 입력용 접힘과 사용자가 고른 집중 모드는 별개입니다. 폰은 입력 중 도구를 접으며 넓은 터치 화면은 화상 키보드로 화면 높이가 충분히 줄었을 때 입력용 접힘을 적용합니다. 입력을 마치거나 회전·창 크기가 바뀌어도 사용자가 고른 집중 상태를 유지합니다. 접힘·복원 때 읽던 줄의 화면 위치를 유지하고, 바닥에 고정해 읽던 대화는 바닥에 둡니다. 같은 탭에서 다시 연 대화는 읽던 위치·집중 상태·초안·첨부 선택을 복원합니다. 읽던 위치와 집중 상태는 현재 탭 메모리에만 남습니다. 설정의 **이 기기에 초안 보관**은 기본으로 켜져 있으며 초안(UTF-8 32KiB 이내)·업로드가 끝난 첨부 참조·전송 확인 번호를 이 브라우저에 7일·최대 50개까지 보관합니다. 새로고침·탭 닫기 뒤 정확한 기기·계정·세션 및 Claude 대화 UUID로 복원하며 전송 확인 중인 메시지는 입력을 잠그고 같은 확인 번호로 상태를 읽습니다. 터미널의 전송 미확인 초안과 업로드 중인 파일 선택은 자동 복원하지 않습니다. 다른 탭의 최신 초안은 상태 갱신이나 늦은 접수 확인으로 지우지 않습니다. 저장 실패를 안내하고, 잠금·인증 만료 또는 보관 설정을 끄면 보관한 초안을 지웁니다. 이미 업로드된 파일은 호스트의 작업 폴더에 남을 수 있습니다.
- 하드웨어 키보드: 입력창에서 ⌘↩(다른 기기는 Ctrl+Enter)로 보내고, 보내는 동안에도 입력창 포커스가 남아 바로 다음 메시지를 쓸 수 있습니다. 보내는 중과 결과 미확인 동안에는 입력창이 읽기 전용이라 내용을 바꾸거나 다시 보낼 수 없습니다. Esc는 입력창에서 빠져나옵니다(한글 조합 중이거나 도구 메뉴가 열려 있으면 그쪽이 먼저입니다). 접힌 입력창의 "⌘↩ 보내기" 안내는 마우스 화면에서는 항상, 터치 화면에서는 화상 키보드가 보내지 않는 키(수식키·Esc·방향키)를 받았거나 화면이 줄지 않은 채 입력창에 글자를 쳤을 때부터 보입니다. 이 판정은 페이지를 다시 열면 초기화됩니다. 질문 카드가 보이면 입력창 밖에서 숫자 1~9로 선택지를 고를 수 있고(목록에 다 안 보이는 선택지 포함), 보내기는 여전히 따로 눌러야 합니다.
- 화면 키보드(특히 삼성 키보드)는 띄어쓰기 전까지 마지막 단어를 한글 조합 중으로 둡니다. 이때도 대화의 보내기를 누를 수 있고, 누르면 터미널 입력줄의 보내기처럼 입력창 포커스를 놓아 키보드가 그 단어를 확정하게 한 뒤 확정된 내용을 보냅니다(이 경우 키보드가 닫힙니다). 1.5초 안에 확정되지 않으면 보내지 않고 알림으로 안내합니다. ⌘↩·Ctrl+Enter는 조합 중에는 보내지 않습니다.
- 목록에서도 하드웨어 키보드로 움직입니다: 검색창에서 ↓는 첫 세션으로, Enter는 첫 세션을 열고, 세션 사이는 ↑↓로 옮깁니다. 대화에서는 입력창 밖의 Esc나 ⌘[로 목록(나란히 보이면 그 세션 카드)으로 돌아갑니다. 한글 조합 중이거나 터미널·창이 열려 있으면 그쪽이 먼저입니다.
- 길게 누르기·오른쪽 클릭 메뉴의 항목은 메뉴가 열린 뒤 그 항목 위에서 시작한 누름으로만 실행됩니다. 메뉴를 연 손가락을 뗄 때 손가락 아래 항목이 실행되지 않습니다. 키보드(Enter·Space) 실행은 그대로 동작합니다. iOS VoiceOver의 두 번 탭은 아직 실기로 확인하지 않았습니다.
- 휴대폰 등 터치 기기에서는 xterm 화면에 직접 입력하지 않고 아래 입력줄을 사용합니다. 모바일 키보드의 한글 조합과 음성 입력은 단어 전체를 다시 쓰는 방식이라 터미널로 반복 전송될 수 있기 때문입니다. 입력줄의 보내기는 한 번 붙여넣은 뒤 Enter를 따로 보내고, 입력은 Enter 없이 붙여넣기만 합니다. 설정에서 터미널 화면 직접 입력을 다시 켤 수 있습니다.
- 음성 입력(마이크 버튼)은 브라우저의 음성 인식(Web Speech API)을 씁니다. 지원하지 않는 브라우저에서는 버튼이 보이지 않고, 키보드의 받아쓰기는 그대로 쓸 수 있습니다. 음성은 브라우저가 정한 음성 인식 서비스(iPad·iPhone은 Apple, Chrome은 대개 Google)가 처리하며 기기 밖으로 나갈 수 있고, 보드 서버로는 오지 않습니다. 홈 화면에 추가한 앱(standalone)에서 동작하는지는 운영체제 버전마다 다릅니다. 거부되면 그 이유와 오류 코드를(Safari 계열은 거부한 단계 — 이 사이트의 권한, 기기의 마이크, 기기의 음성 인식 — 에 맞춰 허용할 곳을. 사이트 권한 거부가 기억돼 있으면 허용 창 없이 바로 거부됩니다), 시작하지 않거나(15초) 결과 없이 멈추거나(10초) 곧바로 끝나면 그 사실을 입력창 상태줄에 표시하고 듣기를 멈춥니다. 그때는 브라우저에서 열거나 키보드의 받아쓰기를 쓰면 됩니다. 받아쓴 글은 커서 위치에 들어가며 보내기 전까지 고칠 수 있습니다. 듣는 동안 입력창이 잠깐 잠겨도(대화 상태를 다시 읽는 중 등) 들은 글은 계속 들어갑니다. 듣는 중에는 입력창이 잠겨도 마이크 버튼으로 끝낼 수 있습니다. 끝내려고 누른 뒤에는 "받아쓴 글을 마무리하고 있습니다…"를 보이며 마지막 결과를 최대 8초 기다리고, 그 사이 다시 누르면 인식을 즉시 중지하고 새로 시작할 수 있습니다. 아직 끝나지 않은 인식기의 늦은 결과는 입력창을 바꾸지 않습니다. 말을 쉬었다 이어 해서 브라우저가 결과 목록을 새로 시작해도 앞에 확정된 글은 남고, 확정 전 결과가 합쳐지거나 Android가 같은 말을 처음부터 다시 보내도 한 번만 들어갑니다. 다른 방법으로 입력창 글이 바뀌어 멈추면 그 이유를 상태줄에 보입니다. Android(특히 삼성 음성 인식)는 연속 듣기를 요청해도 한 마디가 확정되면 인식을 스스로 끝내므로, Android에서는 사용자가 끝내지 않았는데 끝나면 같은 자리에서 이어 듣습니다(받아쓴 글 유지, 말 없이 10초가 지나거나 권한·네트워크 같은 오류가 나거나 화면을 떠나면 멈춤, 들은 말 없이 30번 연달아 다시 시작되면 멈춤). 기기에 따라 다시 들을 때마다 시작음이 날 수 있습니다. Android 키보드는 직접 치지 않은 글을 고쳐 쓰거나 다시 확정해 받아쓰기를 끊을 수 있고, iPadOS는 화면 키보드가 열려 있으면 음성 인식이 시작돼도 소리를 넘기지 않아(보낸 뒤 입력창에 포커스가 남은 채 다시 누를 때 등) 아무것도 받아쓰지 못합니다. 그래서 터치 기기에서는 듣는 동안 대화 입력창의 키보드가 입력창을 놓습니다. 또 iPad 실기 로그에서는 인식이 시작·오디오 이벤트만 보내고 오류 없이 결과를 주지 않는 상태가 있었습니다. 이 상태는 받아쓰기가 끝난 직후(연달아 두 번째)에 생겼고, 요청 직후(0.1초 이내) 오디오 시작을 알렸습니다(정상 시작은 약 0.2초). 기다리기(12초)나 새 인식(같은 페이지·새 iframe 모두)으로는 풀리지 않았고, 새로고침이나 약 40초 뒤에 풀렸습니다. 그래서 iPad·iPhone에서는 듣기를 끝내도(마이크 다시 누름·보내기·명령·다른 입력창) 인식 엔진을 1분 동안 끄지 않고 대기시킵니다. 대기 중에는 기기의 마이크 표시가 켜져 있지만 들린 말은 입력하지 않고, 상태줄에 "마이크 대기 중"을 보입니다. 그 안에 마이크를 다시 누르면 같은 엔진이 바로 이어서 받아쓰고(어느 입력창이든 그 커서 위치에), 1분이 지나거나 화면이 숨겨지거나 보드가 잠기거나 엔진이 스스로 끝나면 끕니다. 대기 중 엔진이 오류를 알리면 다음 누름은 그 엔진을 버리고 새로 시작합니다. 이어서 받아쓸 때 WebKit이 결과 목록을 새로 시작하면(앞 결과의 글이 달라지면) 대기 전 결과를 건너뛰지 않고 새 말로 받아씁니다. 마이크를 다시 눌러 끝낼 때는 마지막 말이 들어오도록 0.8초 기다린 뒤 대기하고, 보내기·명령은 보낸 글 뒤에 말이 붙지 않게 바로 대기합니다. 그래도 고장 상태로 시작하면 침묵 10초를 기다리지 않고 바로 멈추며 "잠시 뒤 다시 누르거나 보드를 새로고침해 주세요"라고 안내합니다. 진단 기록에는 플랫폼 오류 메시지를 원문 대신 종류·해시·길이 코드로, 누를 때 화면 키보드·포커스 위치와 직전 듣기의 종료 방식·경과 시간을 남깁니다. 터미널 입력줄도 iPad·iPhone에서는 키보드 크기 추정이 틀려도 포커스를 놓습니다. 음성 입력 중 입력창에 포커스가 없더라도 하드웨어 키를 CLI로 직접 보내지 않습니다. 엔진 대기도 결과를 보장하지 않으며(원인은 플랫폼 음성 인식 안에 있음), 준비·듣기·마무리·대기를 구분해 안내합니다. 마이크로 듣는 동안에는(키보드 입력과 달리) 화면 전체에 큰 마이크 화면을 띄워 듣는 중인지와, 이번에 받아쓴 말을 큰 글씨로(입력창에 원래 있던 글의 끝은 작게 앞에) 보여 주며, 그 화면의 **보내기**는 마지막 말이 들어온 뒤(iPad는 엔진 대기, 그 밖은 듣기 종료) 그 입력창의 보내기(대화는 메시지 보내기, 터미널 입력줄은 입력하고 Enter)를 한 번 누르며, 보낼 수 없는 상태(빈 입력, 전송 중 등)면 보내지 않고, 한글 조합 중인 단어는 그 보내기처럼 먼저 확정합니다. 보내기를 누른 뒤라도 듣기가 오류로 끝나거나, 입력창이 화면을 떠나거나, 입력창 글이 다른 방법으로 바뀌어 멈추면 보내지 않습니다(들은 말 없이 끝나면 입력창에 있는 글을 보냅니다). 마무리 중에 **보내지 않고 끝내기**를 누르면 앞서 누른 보내기도 취소됩니다. **보내지 않고 끝내기**는 마이크를 다시 누른 것과 같습니다. 알림(토스트)은 그 화면 위에 보입니다. 키보드가 입력창을 놓으면서 갖고 있던 글을 다시 써도, 받아쓴 글이 들어가기 전이면 그 글을 그대로 두고 계속 듣습니다. 글을 직접 바꾸거나(타이핑·붙여넣기) 보내기를 누르거나 화면을 떠나면 듣기를 멈춥니다. 마이크를 쓸 때마다 그 진단 기록(인식 이벤트 이름·시각, 결과 개수, 글자 수, 오류 코드, 입력 종류, 입력창 잠금·조합 상태, 상태줄 안내 코드 — 말한 내용은 없음)을 보드 상태 폴더의 `dictation-trace.jsonl`(소유자 전용, 약 1MB를 넘으면 이전 파일 하나로 넘김)에 남깁니다. 기기마다 다른 음성 인식 동작을 확인하기 위한 것입니다. 터치 기기에서 화면 키보드가 열릴 때도 화면 크기·스크롤 위치·입력창 위치(숫자만)를 같은 파일에 남깁니다. 같은 입력창에서 같은 크기(모든 값이 4px 이내)로 이미 남긴 기록은 다시 남기지 않으며, 한 화면에 4번까지입니다. iOS가 키보드를 위해 페이지를 밀어 올리면, 키보드가 열려 있는 동안 채팅과 터미널 화면이 함께 보이는 영역을 따라갑니다. 포커스가 풀려도 Safari가 스크롤 위치를 실제로 되돌릴 때까지 보정을 유지합니다. 나란히 보기의 숨기기는 이전 브라우저 기록 없이도 터미널 칸을 숨기며, 실행과 초안을 유지합니다. 터미널 헤더의 탭은 키보드 포커스 이동으로 버튼 위치가 바뀌지 않도록 유지한 뒤, 숨김 또는 닫기 확인창에서 포커스를 정리합니다. Android Chrome이 앞서 들은 말을 다음 결과에 되풀이하는 경우에만 겹친 부분을 합치며, 이때 일부러 같은 말을 두 번 이어 말하면 한 번만 남을 수 있습니다.
- 특수키는 두 줄(Esc·Tab·⇧Tab·Ctrl+C/J/U/X/L, 역T자 방향키, Enter)입니다. 화면을 쓸어 넘기거나 휠을 돌리면, 대체 화면을 쓰며 마우스를 받는 CLI(Claude·Codex 화면 등)에는 휠 신호를 보내 CLI가 스스로 스크롤하게 하고, 그 밖의 화면은 tmux 기록(최대 2만 줄)을 스크롤합니다. 손가락을 튕기면 관성으로 이어지며, 기록을 보는 동안 실시간으로 돌아가는 버튼이 표시됩니다.
- 출력 연결이 끊기면 최대 6회까지 자동으로 다시 읽습니다. 입력은 결과가 불확실하면 다시 보내지 않습니다. 보드 서버가 다시 시작돼 입력이 보안 토큰 만료로 거절되면, 그 입력과 뒤에 대기 중이던 입력은 보내지 않고 연결은 유지합니다. 새 토큰을 받아 두므로 다음 입력부터 들어가며, 거절된 입력은 다시 입력해야 합니다.
- 다른 기기의 터미널은 터미널마다 따로 SSH 연결을 쓰고, 응답이 약 2분(15초 × 8회) 없을 때까지 기다립니다. 그래서 노트북 뚜껑을 잠깐 닫거나 네트워크가 바뀌어도 이어지고, 연결 하나가 끊겨도 다른 터미널은 영향을 받지 않습니다. 목록 수집은 짧은 대기(약 15초)의 공유 연결을 그대로 씁니다.
- tmux가 있는 Mac에서는 보드가 그 기기에 여는 실행(새 세션·다시 연 대화·연결·인계·이전)을 처음부터 그 기기의 보드 전용 tmux 서버(`tmux -L sessionholic-hold -f /dev/null`, 사용자 tmux와 별개, 상태줄·prefix·마우스 없음) 안에서 시작합니다. 실행 명령과 환경 변수는 비공개 일회용 파일로 넘기고 tmux 인자에 싣지 않습니다. 그래서 그 기기가 잠들거나 연결이 오래 끊겨도 실행은 그 기기에서 계속되고, 보드 터미널은 "기기 연결이 끊겼습니다 · N초 뒤 다시 연결합니다"를 보이며 2·5·10·20·30초 간격으로 다시 붙습니다. 다시 붙기는 그 기기의 tmux로 바로 접속만 하며(배포로 바뀌는 도우미 파일을 쓰지 않음) 아무것도 새로 시작하지 않습니다. 실행이 그 사이 끝났으면 터미널도 끝납니다. 끊긴 동안 입력한 키는 버리고, 그동안 보드의 Claude 보내기는 "다시 연결하는 중"으로 보내지 않습니다. 다시 붙는 동안에도 터미널은 열린 것으로 보이고, 그 화면에서 Ctrl+C를 누르면 다시 붙기를 그만두고 그 기기의 실행도 끝납니다. 처음 연결 자체가 15초 안에 실패하면 다시 시도하지 않고 끝냅니다. 보관 tmux는 보드 터미널 화면에 대체 화면 없이 그려, 실행이 끝나도 마지막 출력이 터미널에 남고 일반 출력도 보드 기록 스크롤로 볼 수 있습니다. Claude Code·Codex처럼 마우스를 쓰는 화면은 휠이 그 앱으로 갑니다. 터미널을 닫으면(실행 종료·연결 닫기) 그 기기의 보관 실행도 끝내고, 그때 기기가 연결돼 있지 않으면 "실행 기기에 연결되면 그 기기의 실행도 종료합니다"라고 알린 뒤 기기가 돌아오면 정리합니다. 보드는 5분마다 자기가 만든 보관 실행만 살펴, 사용자가 닫았거나 보드가 정리한 터미널의 것은 바로, 스스로 끝난 터미널의 것이나 기록이 없는 것은 하루 뒤 정리합니다(다른 보드의 것은 건드리지 않음). 같은 청소가 1시간에 한 번 각 Mac(보드 기기 포함)에서 테스트가 남긴 것도 정리합니다. 테스트가 사용자 임시 폴더에 만든 폴더 바로 안의 Codex 홈(`<임시 폴더>/tmp…/.codex…`)에서 1시간 넘게 도는 앱 서버와, 서버 없이(연결 거절) 하루 넘게 남은 테스트용 tmux 소켓 파일(`sb-test-`·`sb-browser-`·`sb-validation-`)만 대상입니다. 사용자의 Codex 홈과 보드·사용자의 tmux 서버는 건드리지 않습니다. 다른 도구가 임시 폴더의 `tmp…` 폴더 바로 안에 Codex 홈을 두고 1시간 넘게 쓰면 그 앱 서버도 끝납니다.
- tmux 소켓 이름을 기록하기 전에 저장된 아주 옛 터미널 기록은 예전 이름의 tmux에서 아직 돌 수 있어, 현재 tmux에서 못 찾았다는 것만으로는 닫지 않습니다. 보드가 시작될 때 기록마다 한 번 이 사용자의 다른 살아 있는 tmux 서버도 살펴, 어디에도 없으면 끝난 터미널로 기록합니다.
- tmux가 없는 기기나 PC에서는 실행이 SSH 연결 안에서 돌아, 그 기기가 2분 넘게 잠들면 연결이 끊기고 보드에서 새로 연 세션·다시 연 대화는 실행이 끝납니다(대화 기록은 남습니다). 기존 작업에 붙은 연결(attach)이 끊기면 보기만 끝나고 작업은 계속됩니다.
- 끝난 터미널에는 이유(10분 미사용으로 정리했는지, 실행 기기와의 연결이 끊겼을 수 있는지)와, 그 세션이 목록에 있으면 **이 세션 다시 열기** 버튼을 보여 줍니다. 다시 열기는 새 터미널처럼 실행 계획을 확인한 뒤 엽니다.
- 오래 백그라운드에 있던 화면(홈 화면 앱 등)이 다시 보이면, 브라우저가 온라인 알림을 놓쳤더라도 실제로 연결돼 있으면 오프라인 표시를 풀고 목록·대화를 다시 읽으며 실시간 연결도 새로 시작합니다.
- 보드 터미널은 기본 16개(`--max-terminals`로 1~32)까지 동시에 엽니다. 가득 찬 상태에서 새 터미널을 열면 기존 세션에 붙은 연결(`연결 닫기`로 닫을 수 있는 attach 연결, Codex 연결 제외) 중 1분 넘게 화면 읽기·입력이 없던 가장 오래된 연결을 닫고 자리를 만듭니다. 이 정리는 보드의 연결만 닫으며 기존 세션에 중단 명령을 보내지 않고, 사용자 종료로 기록하지 않아 그 세션의 재개를 막지 않습니다. 다음 입력 때 **터미널 열기**로 다시 연결합니다. 보드에서 직접 실행한 새 세션·인계·이전·재개 터미널과 실행 준비 중인 터미널은 자동으로 닫지 않으며, 정리할 연결이 없으면 열린 터미널 수와 함께 안내합니다.
- 보내기·질문 불러오기로 보드가 연 Claude 세션 연결은 10분 동안 화면 읽기·입력이 없으면 공간과 상관없이 닫습니다(세션은 계속 실행). Codex 연결은 사용자가 직접 연 TUI라 자리를 만들려고 닫지 않고, 30분 동안 화면 읽기·입력이 없으면서 그 세션이 쉬는 중·끝남이거나 목록에 없을 때(보관 등)만 닫습니다(마지막 목록 기준, 그 기기의 목록을 5분 안에 읽지 않았거나 읽기에 실패했으면 닫지 않음: 화면을 보는 기기가 없으면 목록을 읽지 않으므로 그동안은 닫지 않음). 이때 보드의 TUI 클라이언트만 끝나고 대화는 프로젝트의 Codex 서버에 남습니다. 열린 터미널 시트에서는 이 연결들을 "세션 연결 N개" 한 줄로 접어 두고, 사용자가 연 터미널만 바로 보여 줍니다.
- 새 세션 터미널이 실제로 무엇을 실행하는지는 그 기기의 프로세스 목록(`ps`, 보드 사용자의 프로세스만)에서 터미널을 연 시각에 시작된 실행기 아래의 첫 CLI로 읽습니다(기기마다 1분에 한 번, 화면을 기다리게 하지 않음). Claude 에이전트 목록(`claude agents`)이면 "Claude 에이전트 목록 · 폴더"로 이름을 붙이고, 같은 기기·같은 폴더의 목록 화면이 두 개 이상이면 나중 것에 "같은 화면이 이미 열려 있어요"를 표시합니다. 실행기를 하나로 특정할 수 없으면 추정하지 않습니다. 새 세션 시트는 그 기기에 이미 열린 새 세션 터미널을 함께 보여 주어 같은 화면을 다시 열지 않게 합니다. Windows 기기는 아직 읽지 않습니다. 실행기 아래의 SSH 연결(다른 기기에서 연 세션)도 그 터미널의 실행으로 읽고, 실행기는 찾았지만 그 아래에 아무것도 없으면 메뉴에서 기다리는 중으로 기록합니다.
- 새 세션 터미널은 실행 중인 일이 없을 때만 보드가 닫습니다(5분마다 확인, 종료 사유는 보기 연결 정리와 같은 `released`라 세션 재개를 막지 않고, 다른 기기에 남긴 실행 보관도 함께 끝냄). 메뉴에서 아무것도 고르지 않고 아무 입력도 없는 터미널은 화면 읽기·입력 없이 10분, Claude 에이전트 목록(`claude agents`, 목록의 세션은 Claude 데몬 아래에서 계속 실행)은 30분이 지나면 닫습니다. Claude·Codex·SSH 연결을 실행 중인 터미널, 실행을 읽지 못했거나 15분 넘게 다시 읽지 못한 터미널, Windows 기기의 터미널은 닫지 않습니다. 보드가 다시 시작되면 미사용 시간을 처음부터 다시 셉니다. 같은 기기에서 새 세션을 다시 누르면, 10분 안에 연 같은 실행 설정의 터미널이 아직 메뉴에서 기다리는 중이고 아무 입력도 없을 때는 새로 만들지 않고 그 터미널을 엽니다(Windows 기기는 메뉴를 읽지 않아 항상 새로 엽니다). 대화 화면의 **터미널 열기**는 그 세션에 살아 있는 보드 터미널이 있으면(목록의 '터미널 열림' 표시와 같은 판단, 새 세션 터미널을 시작 시각으로 추정 연결한 것 포함) 새 연결을 만들지 않고 그 터미널을 엽니다(추정이면 그렇다고 안내). 그 세션에서 시작했지만 다른 세션을 실행 중인 터미널(인계·이전으로 만든 새 세션)은 그 새 세션의 것이라, 원래 세션의 표시나 터미널 열기에 쓰지 않습니다. 서버도 같은 세션에 정확히 연결된 살아 있는 터미널(인계·재개로 연 실행 등)이 있으면 새 연결 대신 그 터미널로 다시 연결합니다. 실행 중인 새 세션 터미널은 그 세션을 목록에서 지워도 닫지 않습니다(실행 중인 작업이 끝나기 때문). 세션이 끝나면 그 프로그램과 함께 터미널도 끝납니다.
- 열린 터미널의 이름은 보드가 그 터미널의 세션을 알면 그 세션의 표시 제목(제목 수정 포함)을 따르고, 새 목록을 받을 때 함께 바뀝니다. 세션을 알 수 없는 새 세션 터미널은 실행기 이름과 연 시각으로 구분합니다. Claude의 `claude agents`처럼 한 터미널이 여러 세션을 관리하는 실행기는 특정 세션 하나로 연결하지 않습니다.
- 자동 정리가 닫지 않는 터미널(SSH 연결, Codex TUI, 같은 세션의 두 번째 연결 등)은 열린 터미널 목록 아래 **터미널 정리**로 직접 닫습니다. 열린 터미널마다 보드가 아는 세션과 사용하지 않은 시간(보드가 마지막으로 시작된 뒤부터 셈)을 함께 보여 주고, 남은 터미널을 미리 골라 둡니다: 세션이 연결되지 않고 10분 넘게 쓰지 않은 셸(SSH, 메뉴 대기)과 Claude 에이전트 목록 화면, 끝난 세션의 터미널, 보드 목록에 없는 세션에 붙은 연결(2분 넘게), 같은 세션의 두 번째 터미널(지금 화면의 것 > 실행을 맡은 것 > 최근에 쓴 것 하나를 남김), 같은 Claude 에이전트 목록의 반복 화면입니다. 지금 화면에서 연 터미널과 작업 중·답 필요 세션을 실행하고 있는 터미널은 닫으면 실행이 끊기므로 고를 수 없습니다. 목록에 없는 세션을 실행하는 터미널(보관한 세션 등), 아직 세션을 확인하지 못한 Claude·Codex 실행, 실행 중인 프로그램을 읽지 못한 터미널, 쉬는 세션·실행 상태 확인 전 세션의 터미널, 작업 중 세션에 붙은 연결은 표시만 하고 고르지 않습니다. 정리로 닫는 것은 각 행의 닫기와 같아서, 세션을 실행하던 터미널을 닫으면 그 세션은 기본 목록에서 내려가고 보드가 자동으로 다시 시작하지 않습니다. 판단은 마지막으로 받은 세션 목록 기준이며, 목록을 읽지 못한 기기의 터미널은 그 기기에서 아직 실행 중일 수 있어 미리 고르지 않습니다. 인계·이전으로 연 터미널은 원래 세션이 아니라 그 터미널이 실행하는 세션으로 판단합니다. 사용자가 바꾼 선택은 목록이 갱신돼도 유지되며, 고른 터미널을 각 행의 닫기와 같은 요청으로 하나씩 닫은 뒤 닫은 수와 결과를 확인하지 못한 수를 알려 줍니다.

- 입력 요청 ID와 내용의 해시를 로컬 SQLite에 먼저 기록한 뒤 PTY에 씁니다. 입력 원문은 이 기록에 저장하지 않습니다. 부분 입력 실패·응답 유실·서버 재시작 뒤 같은 요청은 다시 입력하지 않으며, 결과 미확인은 실제 터미널에서 확인해야 합니다.
- 기록은 최대 25만 건, 데이터베이스는 최대 64 MiB입니다. 한도에 도달하면 새 입력을 거절합니다. 실행 종료를 확인한 터미널의 기록은 해당 터미널을 닫거나 목록을 새로 읽을 때 정리합니다. 살아 있는 터미널의 기록을 시간만으로 삭제하지 않습니다.
- 하나의 상태 폴더는 보드 프로세스 하나만 사용합니다. 포트만 바꿔 같은 상태 폴더로 두 보드를 실행할 수 없습니다.
- 읽은 대화의 보관본(`conversations.json`)은 읽은 요청이 쓰지 않고 몇 초(5초) 묶어 따로 저장합니다. 정상 종료는 남은 것을 저장하지만 서비스 재시작처럼 프로세스가 바로 끝나면 마지막 몇 초 동안 읽은 대화는 남지 않을 수 있습니다. 이 파일은 기기에 닿지 않을 때 보여 줄 보관본일 뿐이라, 연결된 기기의 대화는 다시 읽습니다. 전송·명령 기록과 인계·이전 표시처럼 한 번만 처리해야 하는 기록은 디스크에 동기화한 뒤 바꿉니다(macOS의 `fsync`는 디스크 자체의 쓰기 캐시까지 비우지는 않습니다).
- 서버 기록 파일을 비울 때(20MB 초과) 서버 자신이 쓰는 줄은 잃지 않도록 기다리게 하지만, 서버가 띄운 하위 프로세스가 같은 파일에 직접 쓴 줄은 그 순간에 잃을 수 있습니다.
- 실시간 연결이 끝날 때마다 사유(`client`·`write`·`timeout`·`server`·`error`)·연결 시간·대화를 따라갔는지·보낸 변경 알림 수를 서버 기록에 한 줄 남깁니다. 어떤 대화인지, 접속 주소, 쿠키는 남기지 않습니다. 브라우저가 스스로 닫은 연결(다른 대화를 열거나 화면을 숨기거나 새로고침)은 모두 `client`로 보이며 서버는 그 이유를 구분하지 못합니다.

## 검증 상태

- 원본 개인 개발 환경에서는 Codex CLI 0.161.0과 0.160.1의 격리 세션 검증 기록이 있습니다. 이 기록은 현재 공개 후보 빌드에서의 재검증이나 해당 버전만의 지원 보증이 아닙니다.
- 공개 후보 자체의 CLI 버전별 호환성, 다양한 macOS·네트워크 구성, 실제 사용자 데이터 이전은 아직 독립적으로 확인되지 않았습니다.
- 이전 개인 모바일 검수는 특정 기기의 일부 파일 첨부·입력 동작에 한정됩니다. 공개 후보의 모바일 브라우저 전반, 클립보드 권한, 키보드·IME, 잠금과 망 전환을 입증하지 않습니다.
- 자동 테스트, fixture, echo 터미널 검증은 실제 사용자 계정·모델 turn·모바일 하드웨어 검증을 대신하지 않습니다.

지원 범위는 native CLI와 OS 버전에 따라 달라질 수 있습니다. 새 버전으로 갱신하기 전에는 별도 테스트 계정과 합성 작업공간으로 확인하세요.

보드 상단의 짧은 **새로고침** 버튼과 채팅 헤더의 새로고침 아이콘으로 저장된 웹 화면을 지우고 최신 화면을 다시 받을 수 있습니다. 별도 버튼 줄은 없으며, 기기 연결·사용량·하드웨어·목록 업데이트는 상단 **기기** 보기에서 확인합니다. 기기 보기에는 등록 수와 연결 수를 구분하고, 연결이 끊긴 기기도 이름과 상태를 남깁니다. 목록의 **새 세션**은 제목 옆에 있습니다. 설정 안의 같은 버튼도 유지합니다. 보내지 않은 초안·첨부나 확인 중인 입력이 있으면 먼저 확인창을 띄우고 보관 성공 시 **초안 보관 후 새로고침**을 제공합니다. 보관이 꺼졌거나 저장 실패·업로드 진행 중이면 버리기 전에 안내합니다. 실행 중 모든 새로고침 버튼을 잠가 중복 실행을 막습니다. 대화 기록·실행 중인 세션·개인 설정·알림 구독은 유지합니다.
