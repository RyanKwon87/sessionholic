# 텍스트 대화 보존과 자동 정리

완료된 세션의 전체 텍스트 대화와 요약을 보존하고, 14일 미사용 및 7일 유예·변경 검증을 거친 원본 기록을 정리하며, 보드에서 보존 취소와 지난 대화 열람을 제공한다.

## 범위와 구조

- 새 파일 `session_history.py`: 개인 상태 디렉터리의 압축 텍스트 아카이브, 원자적 저장·잠금·보존 정책·유예 상태·검증·요약. 실제 프로젝트 파일과 이미지·영상·음성 바이너리는 보존 대상에서 제외한다.
- 새 파일 `history_native.py`: 실행 기기의 전체 대화 추출·원본 변경 감지·정확한 세션 범위 확인·원본 기록 정리. 도구별로 검증한 동작만 허용하며 프로젝트 전체 정리 명령은 사용하지 않는다.
- 수정 `transfer.py`, `transfer_worker.py`: 기존 인증된 기기 RPC에 대화 보존·검증·정리 동작 추가. 임의 파일 경로를 브라우저에서 받지 않는다.
- 수정 `server.py`: 주기 실행, 정책·보존·지난 대화 조회 API와 종료·오류 처리. 원격 기기는 현재 상태를 확인할 때만 처리한다.
- 수정 `web/index.html`, `web/app.js`, `web/style.css`: 설정의 자동 정리 및 지난 대화 보기, 정리 예정과 보존 선택.
- 새 회귀 테스트: 전체 추출, 첨부 바이너리 제외, 중복·부분 실패, 유예·변경·보존 취소, 실행·미확인 상태 차단, 인증·입력 검증, 보드 UI 계약.
- 수정 `README.md`, `docs/limitations.md`, `scripts/public-files.json`: 지원 범위와 공개 파일 목록. 개인 계정·주소·운영 대화는 저장소에 넣지 않는다.
- 삭제하는 저장소 파일 없음. 실제 사용자 세션은 테스트 대상으로 삼지 않는다.

## 순서와 검증

1. 기존 native 대화 형식과 기기 RPC를 확인하고 전체 추출·정리 범위를 구현한다. 합성 fixture로 이미지뿐인 메시지·긴 대화·하위 기록·불명 상태·파일 경계 및 변경 감지를 확인한다.
2. 압축 텍스트 보존과 정책 상태 기계를 구현한다. 임시 홈에서 14일 + 7일, 보존 지정, 재사용, 백업 손상, 중복 실행·재시작을 검증한다. 요약은 보존 텍스트의 목적·최근 요청·최근 결과·산출물 참조를 근거와 함께 추출해 모델 호출 없이 생성한다.
3. 서버와 기존 RPC에 연결한다. 인증 및 권한 경계, 신선한 원본 상태 확인, 실패 시 원본 유지, 성공 후 아카이브 열람을 HTTP 테스트로 확인한다.
4. 설정·지난 대화 UI를 연결하고 보존/해제와 원본 정리 후 대화 읽기를 프런트엔드 회귀로 검증한다.
5. 변경 관련 테스트 후 Python 전체, Node 전체, 공개 파일 검사와 diff 검사를 실행한다. 런타임·배포 경로는 개인 운영 기록의 대상과 현재 상태를 확인한 뒤 처리한다.

## 적용 기준

- 보드의 목록 숨김이나 터미널 연결 종료만으로 원본 종료를 판단하지 않는다. 부모/하위 중 활동·보존·상태 불명이 하나라도 있으면 정리를 미룬다.
- 요약과 전체 텍스트 대화 저장·검증이 모두 성공해야 유예를 시작한다. 삭제 전 원본 및 보존 상태를 다시 확인하며 변경되면 유예를 취소한다.
- 텍스트 아카이브는 원래 native 세션의 동일 ID 복원을 보장하지 않는다. 전체 대화 읽기와 새 대화로 이어가기 위한 기록이다.
- 원본 사진·영상·결과물·의존성·worktree를 삭제하지 않는다. 실제 파일의 선택적 Drive 백업과 세션 대화 보존은 별도 기능이다.
- API가 조건부 삭제를 제공하지 않으면 확인과 삭제 사이의 외부 재개 경쟁 조건이 남는다. 검증할 수 없는 도구/저장 형식은 백업만 수행하고 정리를 보류한다.

셀프 리뷰: 기존 사용자 변경을 보존하기 위해 별도 worktree에서 진행한다. 프로젝트 파일 백업·클라우드 업로드·임의 원본 실행 종료는 이번 자동 정리에 포함하지 않는다. 데이터 유실과 상태 경계를 검증하는 합성 테스트가 필수다.
