# 지원 범위와 한계

세션홀릭(Sessionholic)은 개인이 소유한 macOS 중심 환경에서 로컬 native CLI 세션을 모아 보고, 기존 세션에 연결하거나 새 환경에서 맥락을 이어가는 self-hosted 도구입니다. 여러 사용자가 공유하는 서비스나 공개 인터넷 서비스가 아닙니다. macOS 실행 호스트에는 사용자가 직접 설치하고 로그인한 Claude Code 또는 Codex CLI, Python, tmux가 필요합니다. Windows PC의 저장 기록은 기기 연결과 실행 확인을 구분하며 현재 실행을 확인하지 못하면 `실행 확인 전`으로 표시합니다. Windows에서는 정확한 기존 Codex 실행 서버가 확인되면 텍스트 입력·터미널 연결·응답 중단·종료를 제공합니다. 서버에 로드되지 않은 Codex 기록은 같은 프로젝트의 서버가 PC에서 실행 중일 때만 보드 터미널에서 다시 엽니다. 관리자 SSH 세션의 내장 실행은 쓰지 않으므로 서버가 꺼져 있으면 새 세션으로 그 프로젝트를 먼저 열어야 합니다. 실행된 적 있는 프로젝트 서버가 꺼져 있으면 해당 기록에 그 사실을 표시하고, 최근 7일 안에 쓴 프로젝트면 기기 칩도 `확인 필요`로 바뀝니다. 서버 밖에서 도는 `codex exec`는 쓰기 잠금을 연 Codex 프로세스를 Windows 재시작 관리자로 확인해 작업 중으로 표시하며(잠금은 잡지 않음), 수집 주기보다 짧은 실행은 놓칠 수 있습니다. 다른 Codex 프로세스가 쓰고 있는 기록은 다시 열지 않습니다. Windows Claude는 PC에서 실행 중이 아닌 대화형 기록만 보드 터미널에서 `--resume`으로 다시 열고, 그 터미널을 통해 텍스트를 보냅니다. PC에서 실행 중인 Claude에는 연결하지 않으며, 원본 프로세스가 확인된 경우 실행 종료만 지원합니다. 백그라운드 Claude 입력·첨부·기기 간 이전은 지원하지 않습니다. 새 세션은 `hosts.json`의 `launcher`에 적은 PC 실행 명령만 번호 메뉴로 엽니다. 터미널 보조키는 Windows에서 ⌘ 없이 Ctrl·Alt로 표시합니다. 호스트 간 기능은 사용자가 설정한 SSH 연결을 사용합니다.

## 세션 목록의 묶음

- 별도의 작업 탭은 없습니다. 세션에서 목표를 추정해 카드로 만들던 자동 작업 화면은 대부분 세션 하나를 다시 보여 주는 데 그쳐 내렸습니다. 화면 밖에서 대화를 읽던 자동 작업 관찰도 기본으로 꺼져 있으며(`--auto-work`로 켤 수 있음), 이전에 저장한 작업 기록은 지우지 않습니다.
- 세션 목록은 **답 필요 → 작업 중 → 최근 끝남 → 이전** 순입니다. 최근 끝남은 3시간 안에 멈춘(열림·완료·닫힘) 세션이고, 실행 상태를 확인하지 못한 기록은 이전에 둡니다. 3일 지난 기록을 숨기는 기본 기간은 이전 묶음에만 적용해, 오래 기다린 답 필요 세션도 목록에 남습니다. 각 묶음 안은 화면에 보이는 제목 가나다순(숫자는 크기순)이라 세션이 갱신돼도 자리가 바뀌지 않으며, 순서는 제목 수정으로 바꿉니다.
- 보드에서 끝낸 세션은 목록에서도 정리합니다. 세션 관리의 **실행 종료**가 확인됐거나 사용자가 실행 중인 그 세션의 보드 터미널을 닫으면, 최근 끝남에 남기지 않고 3일 지난 기록처럼 기본 목록에서 내립니다. 기존 작업에 붙은 연결의 **연결 닫기**는 작업을 끝내지 않으므로, 그 세션이 작업 중·답 필요가 아닐 때만 정리합니다. 이미 끝난 터미널을 닫는 것은 정리하지 않습니다. 세션 관리의 **목록에서 정리**로 직접 내릴 수도 있고 **목록에 다시 표시**로 되돌립니다. 기록은 보드 상태 폴더(`session-tidied.json`)에 저장돼 모든 기기에서 같습니다. 실행과 대화 기록은 건드리지 않고, 검색이나 '오래된 기록 포함'으로 볼 수 있습니다. 정리한 뒤 2분 안의 갱신은 종료 과정에서 생긴 것으로 보고, 그 뒤 다시 갱신되면(새 메시지 등) 목록에 돌아옵니다. 작업 중·답 필요 세션은 정리 여부와 상관없이 보입니다. 보드에서 연 새 세션은 그 세션에 추정으로 연결돼 있어도 정리 대상에 넣습니다(표시만 바뀌므로). 실행 기기가 잠들어 끊긴 경우처럼 보드에서 끝내지 않은 세션은 그대로 최근 끝남에 남습니다.
- 답 필요·최근 끝남 묶음에서 마지막으로 연 뒤에 바뀐 세션에는 파란 점을 표시합니다. 읽음 기록은 보드 상태 폴더(`session-seen.json`)에 저장돼 모든 기기에서 같고, 처음 연 시점 이전에 바뀐 세션은 읽은 것으로 봅니다. 대화를 열거나, 연 채로 그 세션이 답을 기다리거나 끝나면 읽은 것으로 기록합니다.
- 대화 입력창의 도구 › 빠른 답장은 설정에 적은 문구(한 줄에 하나, 12개까지, 이 브라우저에만 저장)를 입력창에 넣습니다. 자동으로 보내지 않습니다.
- 응답 없이 멈춘 요청은 읽기 30초, 쓰기 45초(보내기 90초, 실행 11분처럼 서버가 원격 작업 뒤 답하는 요청은 그보다 길게) 뒤 실패로 처리해 다음 읽기와 연결 끊김 안내를 막지 않습니다. 배포 전에 연 화면은 새 버전이 있다고 안내하고, 보내지 않은 글·첨부·열린 터미널·열린 창이 없으면 화면으로 돌아올 때 새 화면을 불러옵니다.
- 응답 종료나 전송 접수는 목표 완료가 아닙니다. 끝남은 원본 세션이 작업을 멈췄다는 뜻이며 결과를 검증했다는 뜻이 아닙니다.

## 봇 요청과 권한 경계

- 별도 `bot-sources.json`에 등록한 원장만 읽습니다. 봇 이름·대화 제목으로 일반 세션을 봇으로 추정하지 않습니다. 지원 adapter는 팀 요청 수신함, Slack gateway 세션 DB, Slack 요청 원장입니다.
- 요청 상태는 원본의 접수·처리 상태입니다. 이벤트 처리 완료를 업무 목표 완료로 해석하지 않습니다. 요청자나 채널을 확인할 수 없으면 미확인으로 표시하고 권한은 원래 봇 정책의 설명으로 제공합니다.
- 대화 본문을 암호화한 원장은 키를 읽거나 복호화하지 않습니다. native 세션 ID가 명시되고 해당 계정 DB에서 확인된 경우에만 원래 세션과 연결합니다.
- 봇 요청 목록에는 일반 세션의 입력·재개·터미널·종료 버튼을 제공하지 않습니다. 확인된 봇 native 세션으로 직접 실행하는 API도 거절해 원래 봇의 승인과 사용 범위를 우회하지 않습니다.
- 원장 조회는 소스별 최근 최대 100건, 읽기 전용·시간 제한으로 수행하고 120초간 캐시합니다. 실패한 소스는 사용자의 다시 확인 전까지 자동 재시도하지 않습니다.

## 닫힌 세션 재개

- 기기 오프라인과 세션 종료를 구분합니다. 연결을 확인한 뒤 같은 Codex UUID·계정 홈·작업 폴더를 다시 검증하고 사용자가 누른 경우에만 터미널을 엽니다. 메시지·새 모델 turn을 자동으로 보내지 않습니다.
- 웹보드에서 명시적으로 종료하거나 터미널을 닫은 기록은 재개와 구분합니다. 연결 끊김으로 터미널이 사라진 경우에는 사용자 종료로 기록하지 않습니다. 구버전의 원인 없는 닫힘 기록으로 사용자 종료를 추정하지 않습니다.
- 원본이 보관됐거나 계정·작업 폴더가 맞지 않으면 자동 보관 해제나 다른 계정으로 대체하지 않습니다.

## 세션 중단·종료·보관

- 세션 관리에서 현재 원본의 지원 여부를 확인합니다. **응답 중단**은 진행 중인 turn을 멈추고, **실행 종료**는 확인된 native 실행을 끝내며, **보관**은 보드의 작업을 숨깁니다. 보관은 실행을 멈추거나 원본 기록을 삭제하지 않습니다.
- Codex 응답 중단은 app-server가 확인한 해당 turn만 대상으로 합니다. CLI 실행 종료는 정확한 계정 홈·세션·원본 프로세스를 입증할 수 있을 때 지원합니다. 앱 서버의 세션은 정확한 저장 기록을 확인한 뒤 native thread/archive로 종료·보관할 수 있습니다. 하위 에이전트도 보관을 요청하므로 확인창에 그 범위를 표시하며, 종료 확정은 선택한 세션의 미로드 상태와 보관 기록으로 판단합니다. 공용 daemon 자체를 종료하지 않으며 식별이 불충분하면 이유를 표시합니다.
- Claude의 응답만 중단하는 공식 제어는 현재 지원하지 않습니다. 확인된 백그라운드 실행 또는 정확하게 식별한 native CLI는 실행 종료를 사용할 수 있습니다. 원본을 확인할 수 없거나 이미 끝난 세션이면 실행하지 않습니다.
- 미리보기 후 원본 turn·프로세스가 바뀌면 제어를 거절합니다. 결과가 유실되거나 원본 종료를 확인하지 못하면 미확인으로 남기며 자동 재전송·강제 종료하지 않습니다. 이 기능의 합성 검증은 실제 계정·모든 CLI 버전·원격 프로세스 제어 검증을 대신하지 않습니다.

## 세션 조회와 연결

- 웹보드의 세션 제목은 보드에서 표시할 이름으로 따로 저장합니다. 기기·에이전트·계정 홈·세션 ID가 모두 같은 세션에만 적용하며 원본 CLI의 제목이나 대화 기록을 바꾸지 않습니다. 일반·에이전트 세션에서 수정하고 원래 제목으로 되돌릴 수 있으며, 봇 요청의 제목은 원래 봇의 기록을 따릅니다.
- 세션 목록은 프로젝트·제목·기기·세션 상태를 구분해 보여줍니다. 프로젝트명은 호스트 설정의 라벨이나 기록된 작업 폴더 이름을 사용하고, 짧은 폴더 힌트로 작업 위치를 구분합니다. 별도로 수정하지 않은 제목과 대화 미리보기는 원본 CLI의 값을 사용하므로 현재 작업 내용과 갱신 시점이 다를 수 있습니다.
- 수집기는 설치된 CLI의 로컬 세션 정보를 읽습니다. 세션 형식이나 CLI 동작이 바뀌면 조회·재연결이 제한될 수 있습니다. 오프라인 호스트에서는 마지막으로 저장한 결과가 보일 수 있으며, 오래된 값은 현재 상태로 간주하면 안 됩니다.
- 세션 목록은 **일반 세션 / 에이전트 세션**으로 분리하고 일반 세션을 기본으로 엽니다. 확인된 에이전트 시작 세션만 별도 목록에 넣으며, 출처 미확인 세션은 일반 목록에서 해당 표시를 유지합니다. 검색·상태·기기 필터는 선택한 목록에 적용하며 다른 목록의 검색 결과로 이동할 수 있습니다.
- 시작 주체는 직접 시작·에이전트 시작·출처 미확인입니다. 명시 initiator나 알려진 Codex subagent 구조를 근거로 구분합니다. `cli / interactive`가 사람 시작을, `exec / background`가 에이전트 시작을 뜻하지 않습니다. 현재 워커의 이름과 역할은 시작한 주체와 별도입니다. 부모 참조만 있고 시작 증거가 없으면 출처 미확인으로 남깁니다.
- Windows Claude는 살아 있는 정확한 PID·생성 시각·허용 실행파일과 부모 계보를 검증한 경우에도 에이전트 시작으로 구분합니다. 제목에 리뷰가 있거나 print 모드라는 이유만으로 분류하지 않습니다. 조회 시 이미 부모가 종료됐거나 근거를 확인할 수 없으면 출처 미확인으로 남을 수 있습니다.
- Windows의 일회성 Claude 실행은 명시된 실행 옵션을 확인해 표시합니다. 대화 저장을 끈 실행은 오류 대신 기록 미저장 사유와 실행 상태를 보여 주며 세션 관리를 유지합니다. 후속 메시지·터미널 재개는 제공하지 않으며, 결과는 실행을 요청한 에이전트에서 확인해야 합니다. 저장되지 않은 대화를 복원하지 않으며, 실행 옵션을 확인하지 못한 경우 일반 대화 읽기 오류와 구분할 수 없습니다.
- 실제 수집 adapter는 Codex와 Claude Code입니다. Codex의 구조화 subagent source와 Claude 목록이 제공하는 명시 시작·부모 정보는 전달하지만 Hermes나 모든 자동 실행 기록을 수집하지는 않습니다. 앱 서버가 없는 Codex home은 DB에서 보관되지 않은 모든 source의 최신 25개를 읽습니다. 구버전 daemon이 source 필터를 거절하면 대화형 세션만 표시될 수 있다는 경고를 남깁니다.
- 연결에 실패한 기기는 화면이 열려 있는 동안 점점 길게(약 1분 30초·3분·5분, 이후 5분마다) 기다린 뒤 다음 화면 갱신 때 자동으로 다시 확인합니다. 그 사이에는 반복 접속하지 않으며, 새로고침 버튼은 즉시 다시 확인합니다.
- 같은 탭에서 다시 연 대화는 메모리에 남은 내용을 먼저 보여주고 최신 기록을 확인합니다. 확인 중이거나 연결이 끊긴 경우 이를 표시하며, 기기·계정·세션·작업 폴더가 다르면 이 내용을 재사용하지 않습니다. 잠금이나 인증 만료 시 메모리의 대화도 지웁니다.
- Codex 연결은 확인된 로컬 daemon 세션과 정확한 세션 식별자를 사용합니다. vendor의 cloud Remote 세션, 불명확한 ID, 또는 필요한 daemon 연결이 없는 세션을 임의로 재개하지 않습니다.
- Claude background 세션은 exact attach를 지원합니다. 기존 interactive 세션의 직접 attach는 지원하지 않으며 native 터미널을 사용해야 합니다.
- 계정 전환과 새 세션 생성은 대상 호스트에 이미 준비되어 있는 계정을 사용합니다. 로그인 자격증명이나 provider 설정을 다른 호스트로 복사하지 않습니다.
- 버전 2의 `profiles[].launchEnabled` 또는 `profileRules[].launchEnabled`를 `false`로 두면 프로필과 기록은 남기고 보드의 새 CLI 실행·앱 서버 시작을 거부합니다. 라우터 계정 정책의 중단 계정도 실행하지 않습니다. `hide`는 수집도 숨기고 `excludeSuspended`는 중단 계정 수집을 제외하는 별도 설정입니다. 임의 `launcher.command` 내부의 계정 선택·실행 정책은 그 실행 명령이 담당합니다.
- 보드의 새 세션 터미널과 나중에 나타난 native 대화를 시각으로 짝짓는 연결은 `estimated`이며 정확한 매핑이 아닙니다. 같은 기기에서 거의 동시에 시작된 다른 대화를 가리킬 수 있습니다. 이를 native 대화의 직접 시작 증거나 목표 자동 연결 근거로 사용하지 않습니다. 외부 실행 기록의 launch ID와 보드 요청을 정확하게 연결하는 계약은 아직 지원하지 않습니다.

## 메시지와 첨부

- 에이전트 답변은 기본 Markdown 서식(제목·문단·목록·인용·강조·코드·HTTP(S) 링크)으로 표시합니다. 목록 항목은 들여쓴 이어지는 줄, 빈 줄로 띄운 항목·하위 항목, 들여쓴 코드 펜스를 같은 항목으로 묶습니다. 문단 중간의 번호 줄은 `1.`로 시작할 때만 목록이 되고, `2026. 10. 10.` 같은 날짜 줄은 목록으로 보지 않습니다. 코드 블록은 위쪽 머리 줄에 언어와 복사 버튼을 둡니다. 본문 복사는 인용·강조 기호를 제거하고 링크 주소를 남기며, 코드 복사는 문자·들여쓰기·줄바꿈을 보존합니다. 사용자 입력과 native 대화 원문은 수정하지 않습니다.
- 보드 대화는 메시지당 4,000자까지만 받아 표시합니다. 잘린 메시지에는 일부만 표시됐다는 안내가 붙으며, 전체 내용은 원본 native 세션에서 확인해야 합니다. 코드 블록 중간에서 잘리면 끝의 " …"가 코드의 일부로 보일 수 있습니다.
- HTML과 외부 이미지는 실행하거나 불러오지 않습니다. 표·구분선·참조 링크·맨 URL 자동 링크 등은 완전한 Markdown 렌더링을 지원하지 않으며 텍스트로 남습니다. 답변이 65,536자·1,024행을 넘거나 파싱 한도에 도달하면 전체 원문을 텍스트로 표시하고 복사합니다.
- 대화는 최근 80개 항목(메시지와 도구 실행 기록)까지 읽습니다. 그만큼 찼으면 맨 위에 "최근 80개 항목까지만 보입니다"를 표시합니다.
- 사용자·에이전트 메시지 사이에 이어진 도구 실행 기록은 "도구 실행 7개 · 명령 4 · 파일 수정 2" 같은 한 줄로 접어 둡니다. 누르면 기록이 한 줄씩 펼쳐지고, 긴 기록은 한 번 더 눌러 전체를 봅니다. 펼친 상태는 새 메시지가 와도 유지되며, 길게 누르기 메뉴로 묶음 전체를 복사할 수 있습니다. 서버가 보내는 최근 80행에는 도구 기록도 포함되므로, 도구 실행이 많은 대화는 더 이른 대화가 먼저 잘립니다.
- Codex 기록에는 항목별 시각이 없고 turn의 시작·완료 시각만 있습니다. 그래서 turn의 첫 질문에는 시작 시각, 최종 답에는 완료 시각을 표시하고, 중간 보고·작업 중 추가 입력·도구 기록에는 시각을 표시하지 않습니다.
- 대화 끝의 "··· 작업 중"은 세션이 작업 중이고 화면의 마지막 행이 사용자 메시지(보드에서 보내 아직 기록을 기다리는 말풍선 포함)나 도구 실행 묶음일 때만 표시합니다. 에이전트 답이나 시스템 행이 마지막이면 표시하지 않습니다. 보내지 못한 말풍선과 요청이 이미 끝난 말풍선은 이 판정에서 빼므로 "작업 중"을 붙잡지 않습니다. Claude 백그라운드 세션은 답을 낸 뒤에도 도구·하위 작업이 남으면 계속 작업 중이기 때문입니다. 세션 상태는 입력창 위 상태 문구와 목록 배지에 표시하며, 열어 둔 대화의 상태 확인이 목록보다 새로우면 그 대화의 카드·머리말·상단 개수가 목록 수집을 기다리지 않고 따라갑니다(목록의 상태가 바뀌면 다시 목록 기준). 아직 읽은 기록이 없으면(ID 없는 Claude 세션 등) 세션 상태만으로 표시합니다.
- 보드에서 보낸 메시지는 즉시 말풍선으로 보이고, 대화 기록에 그 메시지가 잡히면 말풍선이 사라집니다. Claude Code는 붙여넣은 이미지 경로를 `[Image #1]` 표시와 이미지로 바꿔 기록하고 `첨부 파일:` 줄을 지우므로, 비교할 때 `[Image #N]`·`[Pasted text #N +M lines]` 같은 입력 표시와 첨부 줄을 빼고 봅니다(이미지 칩이 있는 사용자 말풍선에서는 `[Image #N]`도 그리지 않습니다). 작업 중에 보낸 Claude 메시지는 Claude Code가 대기 입력(`queued_command`)으로만 기록하는 경우가 많아, 사람이 입력한 대기 입력도 사용자 메시지로 보여 줍니다. 중단(Esc)으로 같은 입력이 다시 기록되면 한 번만 보입니다. 보조 판정으로, 서버가 접수를 확인한 Claude 말풍선은 문장을 맞추지 못해도 보낸 뒤 들어온 짝 없는 사용자 메시지와 순서대로 1:1로 짝짓고, 서버가 기록 반영을 확인했거나 보낸 뒤 에이전트 답이 기록됐으면(작업 중이면 1분 뒤부터) 정리합니다. 그래서 다른 곳에서 거의 같은 때 입력한 메시지와 짝이 바뀌어 말풍선이 조금 일찍 사라질 수 있습니다. Codex 말풍선은 요청 ID로만 짝짓습니다(서버가 기록 반영을 확인하면 Codex 말풍선도 정리합니다). 말풍선이 정리되면 입력창 위 "메시지를 접수했습니다" 안내와 전송 첨부 표시도 함께 사라집니다.
- 경과 시간("작업 중 · 12분 34초", 1시간 이상은 시·분)은 정확한 시작 시각이 있는 Codex(진행 중인 turn의 시작 시각)만 표시합니다. Claude는 turn 시작을 기록하지 않아 서버가 마지막 사용자 요청 시각으로 근사하므로 시간 없이 "작업 중"만 표시합니다. 표시가 숨거나 화면이 숨겨지면 갱신을 멈춥니다.
- Claude Code가 `[Request interrupted by user]`·대화 요약(`/compact`)·`!` 셸 명령을 사용자 줄로 기록한 것은 "사용자가 중단함"·"이전 대화 요약으로 이어짐" 안내와 명령 기록으로 표시합니다. `claude agents`가 ID 없이 보여 주는 대화형 세션은 대화를 읽거나 보낼 수 없어 안내 한 줄만 표시합니다.
- 입력창은 기본 1~6줄로 늘어나고 펼치면 최대 11줄까지 사용합니다. 실제 높이는 키보드를 제외한 화면 높이에 맞춰 제한되며 긴 초안은 입력창 안에서 스크롤합니다. 접으면 한 줄로 줄어들고 다시 입력하면 자동 확장됩니다.
- 사용자 메시지의 첨부 여부·개수를 표시하며, 전송 기록과 native 입력이 일치하는 파일은 이름·크기도 표시합니다. 보드가 파일을 보낼 때 덧붙인 `첨부 파일: <경로>` 줄은 말풍선과 복사에서 빼고 파일 이름 칩으로 보여 줍니다. 이전 기록이나 native에서 형식이 변환된 이미지는 이름을 추측하지 않고 일반 이미지 표시로 남깁니다. 전송 전 업로드, 전송 결과 미확인, 접수, 세션 기록 확인은 구분합니다. 기록 확인은 에이전트가 파일 내용을 검토했다는 뜻이 아닙니다.
- 웹 첨부의 이름·크기·종류와 입력 해시는 실행 호스트의 비공개 수신 기록에 보관합니다. 대화 본문·파일 내용·경로는 이 표시용 기록에 저장하지 않습니다. 기기 간 새 세션으로 이전할 때 원본 요청 ID의 첨부 표시 기록을 임의로 연결하지 않습니다.
- Codex 직접 메시지는 native app-server의 `turn/start` 하나로 보냅니다. 세션이 쉬고 있으면 새 turn이 시작되고, 작업 중이면 진행 중인 turn에 입력이 합류해 CLI가 다음 차례에 반영합니다. 보드는 메시지를 따로 예약하거나 대기열에 넣지 않습니다. `/review`·수동 `/compact`처럼 입력을 받을 수 없는 turn이면 보내지 않은 것으로 확정하고 초안을 남깁니다. 직접 입력 가능 여부(`canAcceptDirectInput`)는 실험적 필드라 CLI 업데이트 후 달라질 수 있으며, 처음 보는 turn 상태가 있으면 대화는 계속 보여 주되 입력을 잠급니다.
- 보드 대화는 원본 세션의 기록을 다시 읽어 갱신합니다. 작업 중에는 3초 간격으로 시작해 5·10·20초로 간격을 늘리며 최대 240회 확인하고, 일시 오류 뒤에도 같은 간격으로 다시 확인합니다. 그 뒤에는 상태 다시 확인이나 당겨서 새로고침을 사용합니다. cmux 등의 native 터미널 화면 갱신은 해당 클라이언트가 담당하므로 웹과 표시 시점이 다를 수 있습니다. [OpenAI app-server 문서](https://learn.chatgpt.com/docs/app-server)도 `thread/read`를 이벤트 구독 없이 기록을 읽는 호출로 설명합니다. Codex 기록은 전체를 한 번에 불러오지 않고(`includeTurns`는 rollout 전체를 읽어, 몇 시간 이미지 작업한 세션은 수백 MB가 됩니다) 메타데이터를 읽은 뒤 최근 항목부터 100개씩, 보이는 80줄의 가장 오래된 줄이 속한 turn의 사용자 메시지까지(최대 10쪽) 읽고 turn 상태만 따로 읽습니다. 그래서 가장 오래된 turn은 앞부분이 빠질 수 있습니다. 이 페이지 호출(`thread/items/list`·`thread/turns/list`)이 없는 오래된 Codex와, 예전 형식(legacy)으로 저장돼 페이지로 읽을 수 없는 대화는 이전처럼 전체를 읽습니다. 기기 이전 판정과 세션 관리(응답 중단·실행 종료)는 모든 turn의 상태만 필요해, 항목 없이 turn 목록을 100개씩(최대 200쪽) 읽습니다. 대화가 실행 중이 아닌데 진행 중인 turn이 보이면 전체 기록으로 다시 확인합니다.
- Claude CLI에는 기존 세션에 메시지만 보내는 명령이 없어, 보드가 그 세션에 연결한 tmux 터미널에 붙여넣고 Enter를 보냅니다. 백그라운드 세션에 보드 터미널이 없으면 **보내기**를 누를 때 보드가 그 세션에 `claude attach` 연결을 먼저 열고 이어서 보냅니다. 연결을 열지 못하면 아무것도 붙여넣기 전이므로 보내지 않은 것으로 확정하고 이유와 초안을 남깁니다. **답 필요** 묶음의 카드나 알림으로 Claude 백그라운드 세션을 열면 질문 카드의 "질문 불러오기"를 한 번 자동으로 실행해 선택지를 바로 보여 줍니다. 보드 밖 터미널 앱에서 직접 실행 중인 Claude 세션은 웹에서 입력할 수 없습니다. 터미널 화면에 승인·질문 선택 메뉴(`❯ 1.` 형식)가 떠 있으면 입력이 메뉴 선택으로 처리될 수 있어 보내지 않습니다. 같은 요청은 다시 붙여넣지 않으며, 본문 대신 앞부분의 해시(붙여넣은 그대로, 그리고 입력 표시·첨부 줄을 뺀 문장)만 보관해 대화 기록에서 반영 여부를 확인합니다. 붙여넣기 결과를 받지 못해 "결과 미확인"이던 요청도 대화 기록에서 그 메시지가 확인되면 접수로 바뀌어 전송 잠금이 풀립니다(다시 보내지는 않습니다).
- 승인·질문 메뉴는 보드가 그 세션에 연결한 터미널 화면에서 읽어 대화 화면의 질문 카드로 보여 줍니다. 선택지를 고른 뒤 보내기를 따로 눌러야 하고, 보내기 직전에 화면을 다시 읽어 같은 메뉴일 때만 방향키와 Enter를 입력합니다. 여러 개를 고르는 메뉴, 현재 선택 위치를 알 수 없는 메뉴, 보드 밖 터미널에서 실행 중인 세션은 터미널에서 답해야 합니다. 화면 형식은 CLI 버전에 따라 달라질 수 있습니다. 같은 세션의 보드 터미널로 돌아갈 때는 확인 창 없이 바로 연결합니다.
- 결과가 불명확한 메시지는 자동으로 다시 보내지 않습니다. 수신 여부를 먼저 확인하고, 같은 요청을 반복 제출하지 마세요.
- 서버가 native 전송 전 거절을 확인한 경우에는 초안과 첨부를 남기고 입력 잠금을 해제합니다. HTTP 오류 번호만으로 미전송을 추정하지 않습니다. 잠그기와 인증 만료는 대화·초안을 지우는 별도 보안 동작입니다.
- 텍스트는 메시지당 UTF-8 32 KiB, 첨부 파일은 개별 20 MiB, 메시지당 8개까지입니다. 첨부 파일은 실제 세션의 작업 폴더 아래 보드 관리 디렉터리(`.sessionholic-attachments/`)에 저장됩니다. 작업 폴더가 Git 저장소 안이면 이 디렉터리를 저장소의 `info/exclude`에 한 번 추가해 `git add -A`에 포함되지 않게 합니다. 이 처리는 최선 노력이라 실패해도 업로드는 진행되며, 이미 추적 중이거나 강제로 추가한 파일은 막지 않습니다. 보통 파일은 내용 전체를 메시지에 삽입하는 대신 native CLI가 읽을 수 있는 경로로 전달합니다.

## 인계와 기기 간 이전

- 같은 native 세션에 연결하는 경우 기존 프로세스를 사용합니다. 도구·계정 변경을 위한 인계는 최근 대화와 Git 상태 등의 맥락을 전달해 **새 native CLI 세션**을 실행합니다. 원본 프로세스, 실행 중인 turn, 승인 상태를 새 호스트로 옮기는 기능이 아닙니다.
- 원격 기기 안의 도구·계정 전환도 같은 의미의 인계입니다. 같은 작업 폴더에서 대상 에이전트를 새로 열고 원본 대화는 그대로 둡니다. 인계 문서·Codex app-server·실행 환경 경계·환경 변수는 모두 그 원격 기기 기준입니다. 보드의 실행 계획은 경로 이름만으로 경계를 추정하고, 실제 판정은 실행 직전에 원격 helper가 그 기기의 설정으로 다시 합니다. 추정과 실제 판정이 다르면 실행하지 않습니다. 원격 기기 연결이 끊겼거나 원본이 작업 중·승인 대기면 실행하지 않습니다. Codex 대상은 그 기기의 대상 계정 app-server 연결이 있어야 합니다.
- 원격 인계 준비 응답이 유실되면 첫 지시가 이미 전달됐을 수 있습니다. 보드는 결과를 미확인으로 알리고 자동으로 다시 실행하지 않습니다. 원격 기기의 작업 목록을 먼저 확인하세요.
- 원격 helper는 실행하지 않고 만들어질 명령의 요약만 보여 주는 점검 모드를 제공합니다. `python3 -I <helper.pyz> handoff --check -`에 요청 JSON(`{"source": {"agent", "id", "home", "cwd", "phase"}, "target": {"agent", "account"}}`)을 표준 입력으로 주면 대상 프로필·경계·실행 파일을 확인하고, 실행 파일 이름·작업 폴더·환경 변수 키 목록(값 제외)만 출력합니다. 첫 지시를 보내거나 파일을 남기지 않습니다. 보드가 준비한 요청은 `handoff --check <요청 해시>`로 실행 전 내용을 같은 형식으로 확인할 수 있습니다.
- 기기 간 이전은 원본 응답을 확인하고 중단한 뒤 선택된 작업공간 파일과 최근 대화를 새 목적 폴더로 복사하고 대상 호스트에서 새 세션을 준비합니다. 원본 파일과 기록은 남겨 둡니다. 이는 프로세스 이동이나 완전한 복원 기능이 아닙니다.
- 작업공간 아카이브는 최대 128 MiB, 파일 항목은 최대 20,000개입니다. Git 저장소에서는 Git이 무시하는 폴더와 중첩 저장소·worktree를 세지 않고 복사하지 않습니다. Git이 아닌 폴더에서는 빌드 결과물·의존성·도구 캐시 폴더(`node_modules`, `Pods`, `.gradle`, Cargo·Maven `target` 등)를 제외합니다.
- 이전은 알려진 자격증명과 특수 파일을 제외하고 제한된 크기의 작업공간을 복사합니다. 인증 파일(`.env`, `auth.json`, 개인키, `.ssh` 등)과 프로젝트 `.claude`·`.codex` 폴더의 개인 설정·세션 기록은 복사하지 않고, 공유 설정(`agents`, `commands`, `skills`, `hooks`, `settings.json`, `AGENTS.md`)은 복사합니다. 이름이 자격증명처럼 보이는 미추적 파일(`token`·`secret`·`credential`이 들어간 데이터 파일, `secrets/`, `*.key`, `.envrc`, `*.tfvars` 등)은 제외하고 미리보기에 목록과 경고를 표시합니다. 두 종류 모두 Git이 추적하거나 HEAD 이력에 있으면 번들 이력에 포함되므로 이전 전체를 거절합니다.
- 제외 규칙이 모든 비밀정보를 식별한다고 보장할 수 없습니다. 미리보기의 큰 파일·제외 파일 목록과 경고를 검토하고, 민감한 정보가 없는지 확인하세요.
- 원본이 이전 중 다시 변경되거나 대상이 준비되지 않으면 새 세션 실행을 중단합니다. 이미 중단된 원본 응답은 자동으로 재개하지 않습니다.
- 대상 준비 요청의 응답이 유실되면 이미 대상 작업이 시작됐을 수 있습니다. 보드는 결과를 미확인 상태로 기록하고 같은 요청을 자동 재실행하지 않습니다. 대상 기기의 작업 목록과 이전 기록을 확인한 뒤 다음 작업을 진행하세요. 대상 도우미가 새 세션 연결 전 단계(검증·파일 복원·실행 준비)에서 실패를 직접 보고한 경우에는 그 원인을 실패로 기록하고 대상 임시 파일을 정리합니다.
- 터미널 연결 자리는 대상 실행 준비 전에 확보합니다. 이후 연결 자체가 실패할 수 있으며, 이때는 대상 기기와 준비된 세션 정보를 안내합니다. 새 인계 계획을 명시적으로 실행하면 별도 작업이 만들어질 수 있으므로 먼저 대상 목록을 확인하세요. 모든 단계의 자동 복구를 제공하는 것은 아닙니다.

## 알림

- 설정의 **알림**에서 기기마다 켜고 끕니다. 아이폰·아이패드는 Safari에서 홈 화면에 추가한 앱(iOS 16.4 이상)으로 열었을 때만 켤 수 있습니다. 브라우저가 알림을 막았거나 지원하지 않으면 이유를 표시하고 켜지 않습니다.
- 일반 세션이 답을 기다리기 시작할 때와, 2분 넘게 작업한(시작부터 기록의 마지막 갱신까지) 세션이 멈출 때만 알립니다. 두 번의 수집 사이에 시작해 처음 보일 때부터 답을 기다리는 세션도 알리지만, 보드가 시작된 뒤 그 기기를 처음 읽을 때는 기준으로만 기록합니다. 에이전트가 시작한 세션·봇 요청·일회성 실행·Codex `exec` 실행·30분 넘게 갱신되지 않은 기록은 알리지 않고, 실행 상태를 확인하지 못한 기록은 마지막으로 알던 상태를 유지합니다. 마지막 상태를 저장해 재시작 뒤 같은 알림을 반복하지 않습니다. 실패 신호는 아직 원본 상태에 없어 따로 알리지 않습니다.
- 보드는 서명한 빈 알림 신호만 푸시 서비스로 보내고, 보여 줄 제목·문장은 기기의 알림 처리기가 이 보드에서 직접 읽습니다. 대화 내용은 Apple·Google 등의 푸시 서비스로 가지 않습니다. 그 대신 기기가 보드에 닿지 않거나 로그인이 끝났으면 "확인할 세션이 있어요"만 표시합니다. 알림을 누르면 해당 세션을 엽니다. 알림에는 세션 제목과 마지막 응답 앞부분이 들어가므로, 잠금 화면에 보이지 않게 하려면 기기의 알림 미리보기 설정을 바꿔 주세요.
- 알림을 보낼 때마다 건수와 전달된 기기 수를 보드 기록에 한 줄 남깁니다. 대화를 열어 둔 화면이 있어도 알림은 보냅니다(연결이 조용히 끊긴 화면을 보고 있는 것으로 잘못 알아 알림을 놓치지 않도록).
- 알림을 받는 기기가 하나라도 있으면 화면이 닫혀 있어도 보드 수집 간격마다 기기 목록을 새로 읽습니다. 받는 기기가 없으면 화면 밖에서 수집하지 않습니다. `--no-push`로 실행하면 알림과 화면 밖 수집을 모두 끄고, 설정 화면은 알림을 켤 수 없는 이유를 표시합니다.
- 브라우저가 알려 준 주소 가운데 알려진 푸시 서비스(Apple·Google·Mozilla·Microsoft)의 HTTPS 주소만 받습니다. 푸시 서비스로 가는 요청은 리다이렉트를 따라가지 않습니다. 푸시 서비스가 주소를 없앴다고 답하면(404·410) 그 기기 등록을 지우고, 요청 제한(429)·네트워크 오류·5xx면 알림을 남겨 둔 채 잠시 뒤 다시 깨웁니다. 보드 등록이 사라진 기기는 설정에서 **알림 다시 켜기**를 표시합니다.

## 터미널 입력과 상태 기록

- PC·패드·폰 모두 집중 모드 버튼으로 대화 도구를 접고 복원합니다. PC 본문 클릭은 집중 모드를 전환하지 않습니다. 패드·폰은 대화의 일반 영역을 짧게 탭해도 전환하며, 버튼·링크·코드·첨부·이미지·질문 카드·텍스트 선택·길게 누르기·드래그는 제외합니다. 직접 스크롤하면 부가 도구가 접히고 맨 아래 도달·맨 아래 버튼·새 답변·질문·전송 오류가 숨김 선택을 바꾸지 않습니다. 질문과 전송 오류는 대화·입력창 곁에 표시하고, 짧은 제목·기기·복원·뒤로 가기·최소 입력은 남습니다.
- 입력용 접힘과 사용자가 고른 집중 모드는 별개입니다. 폰은 입력 중 도구를 접으며 넓은 터치 화면은 화상 키보드로 화면 높이가 충분히 줄었을 때 입력용 접힘을 적용합니다. 입력을 마치거나 회전·창 크기가 바뀌어도 사용자가 고른 집중 상태를 유지합니다. 접힘·복원 때 읽던 줄의 화면 위치를 유지하고, 바닥에 고정해 읽던 대화는 바닥에 둡니다. 같은 탭에서 다시 연 대화는 읽던 위치·집중 상태·초안·첨부 선택을 복원합니다. 탭 닫기·새로고침·잠금·인증 만료로 이 메모리 상태는 사라지며 재접속을 위한 장기 초안 저장은 하지 않습니다. 이미 업로드된 파일은 호스트의 작업 폴더에 남을 수 있습니다.
- 하드웨어 키보드: 입력창에서 ⌘↩(다른 기기는 Ctrl+Enter)로 보내고, 보내는 동안에도 입력창 포커스가 남아 바로 다음 메시지를 쓸 수 있습니다. 보내는 중과 결과 미확인 동안에는 입력창이 읽기 전용이라 내용을 바꾸거나 다시 보낼 수 없습니다. Esc는 입력창에서 빠져나옵니다(한글 조합 중이거나 도구 메뉴가 열려 있으면 그쪽이 먼저입니다). 접힌 입력창의 "⌘↩ 보내기" 안내는 마우스 화면에서는 항상, 터치 화면에서는 화상 키보드가 보내지 않는 키(수식키·Esc·방향키)를 받았거나 화면이 줄지 않은 채 입력창에 글자를 쳤을 때부터 보입니다. 이 판정은 페이지를 다시 열면 초기화됩니다. 질문 카드가 보이면 입력창 밖에서 숫자 1~9로 선택지를 고를 수 있고(목록에 다 안 보이는 선택지 포함), 보내기는 여전히 따로 눌러야 합니다.
- 목록에서도 하드웨어 키보드로 움직입니다: 검색창에서 ↓는 첫 세션으로, Enter는 첫 세션을 열고, 세션 사이는 ↑↓로 옮깁니다. 대화에서는 입력창 밖의 Esc나 ⌘[로 목록(나란히 보이면 그 세션 카드)으로 돌아갑니다. 한글 조합 중이거나 터미널·창이 열려 있으면 그쪽이 먼저입니다.
- 길게 누르기·오른쪽 클릭 메뉴의 항목은 메뉴가 열린 뒤 그 항목 위에서 시작한 누름으로만 실행됩니다. 메뉴를 연 손가락을 뗄 때 손가락 아래 항목이 실행되지 않습니다. 키보드(Enter·Space) 실행은 그대로 동작합니다. iOS VoiceOver의 두 번 탭은 아직 실기로 확인하지 않았습니다.
- 휴대폰 등 터치 기기에서는 xterm 화면에 직접 입력하지 않고 아래 입력줄을 사용합니다. 모바일 키보드의 한글 조합과 음성 입력은 단어 전체를 다시 쓰는 방식이라 터미널로 반복 전송될 수 있기 때문입니다. 입력줄의 보내기는 한 번 붙여넣은 뒤 Enter를 따로 보내고, 입력은 Enter 없이 붙여넣기만 합니다. 설정에서 터미널 화면 직접 입력을 다시 켤 수 있습니다.
- 음성 입력(마이크 버튼)은 브라우저의 음성 인식(Web Speech API)을 씁니다. 지원하지 않는 브라우저에서는 버튼이 보이지 않고, 키보드의 받아쓰기는 그대로 쓸 수 있습니다. 음성은 브라우저가 정한 음성 인식 서비스(iPad·iPhone은 Apple, Chrome은 대개 Google)가 처리하며 기기 밖으로 나갈 수 있고, 보드 서버로는 오지 않습니다. 홈 화면에 추가한 앱(standalone)에서 동작하는지는 운영체제 버전마다 다릅니다. 거부되면 그 이유와 오류 코드를, 시작하지 않거나(15초) 결과 없이 멈추거나(10초) 곧바로 끝나면 그 사실을 입력창 상태줄에 표시하고 듣기를 멈춥니다. 그때는 브라우저에서 열거나 키보드의 받아쓰기를 쓰면 됩니다. 받아쓴 글은 커서 위치에 들어가며 보내기 전까지 고칠 수 있습니다. 듣는 동안 입력창이 잠깐 잠겨도(대화 상태를 다시 읽는 중 등) 들은 글은 계속 들어갑니다. 듣는 중에는 입력창이 잠겨도 마이크 버튼으로 끝낼 수 있습니다. 끝내려고 누른 뒤에는 "받아쓴 글을 마무리하고 있습니다…"를 보이며 마지막 결과를 최대 8초 기다리고, 그 사이 다시 눌러도 기다림을 끊지 않습니다. 말을 쉬었다 이어 해서 브라우저가 결과 목록을 새로 시작해도 앞에 확정된 글은 남고, 확정 전 결과가 합쳐지거나 Android가 같은 말을 처음부터 다시 보내도 한 번만 들어갑니다. 다른 방법으로 입력창 글이 바뀌어 멈추면 그 이유를 상태줄에 보입니다. Android 키보드는 직접 치지 않은 글을 고쳐 쓰거나 다시 확정해 받아쓰기를 끊을 수 있어, Android 터치 기기에서는 듣는 동안 대화 입력창의 키보드가 입력창을 놓습니다(iPad·iPhone은 키보드를 유지하고, 터미널 입력줄은 키가 CLI로 바로 가지 않도록 어디서나 포커스를 유지). 글을 직접 바꾸거나(타이핑·붙여넣기) 보내기를 누르거나 화면을 떠나면 듣기를 멈춥니다. Android Chrome이 앞서 들은 말을 다음 결과에 되풀이하는 경우에만 겹친 부분을 합치며, 이때 일부러 같은 말을 두 번 이어 말하면 한 번만 남을 수 있습니다.
- 특수키는 두 줄(Esc·Tab·⇧Tab·Ctrl+C/J/U/X/L, 역T자 방향키, Enter)입니다. 화면을 쓸어 넘기거나 휠을 돌리면, 대체 화면을 쓰며 마우스를 받는 CLI(Claude·Codex 화면 등)에는 휠 신호를 보내 CLI가 스스로 스크롤하게 하고, 그 밖의 화면은 tmux 기록(최대 2만 줄)을 스크롤합니다. 손가락을 튕기면 관성으로 이어지며, 기록을 보는 동안 실시간으로 돌아가는 버튼이 표시됩니다.
- 출력 연결이 끊기면 최대 6회까지 자동으로 다시 읽습니다. 입력은 결과가 불확실하면 다시 보내지 않습니다. 보드 서버가 다시 시작돼 입력이 보안 토큰 만료로 거절되면, 그 입력과 뒤에 대기 중이던 입력은 보내지 않고 연결은 유지합니다. 새 토큰을 받아 두므로 다음 입력부터 들어가며, 거절된 입력은 다시 입력해야 합니다.
- 다른 기기의 터미널은 터미널마다 따로 SSH 연결을 쓰고, 응답이 약 2분(15초 × 8회) 없을 때까지 기다립니다. 그래서 노트북 뚜껑을 잠깐 닫거나 네트워크가 바뀌어도 이어지고, 연결 하나가 끊겨도 다른 터미널은 영향을 받지 않습니다. 목록 수집은 짧은 대기(약 15초)의 공유 연결을 그대로 씁니다.
- tmux가 있는 Mac에서는 보드가 그 기기에 여는 실행(새 세션·다시 연 대화·연결·인계·이전)을 처음부터 그 기기의 보드 전용 tmux 서버(`tmux -L sessionholic-hold -f /dev/null`, 사용자 tmux와 별개, 상태줄·prefix·마우스 없음) 안에서 시작합니다. 실행 명령과 환경 변수는 비공개 일회용 파일로 넘기고 tmux 인자에 싣지 않습니다. 그래서 그 기기가 잠들거나 연결이 오래 끊겨도 실행은 그 기기에서 계속되고, 보드 터미널은 "기기 연결이 끊겼습니다 · N초 뒤 다시 연결합니다"를 보이며 2·5·10·20·30초 간격으로 다시 붙습니다. 다시 붙기는 그 기기의 tmux로 바로 접속만 하며(배포로 바뀌는 도우미 파일을 쓰지 않음) 아무것도 새로 시작하지 않습니다. 실행이 그 사이 끝났으면 터미널도 끝납니다. 끊긴 동안 입력한 키는 버리고, 그동안 보드의 Claude 보내기는 "다시 연결하는 중"으로 보내지 않습니다. 다시 붙는 동안에도 터미널은 열린 것으로 보이고, 그 화면에서 Ctrl+C를 누르면 다시 붙기를 그만두고 그 기기의 실행도 끝납니다. 처음 연결 자체가 15초 안에 실패하면 다시 시도하지 않고 끝냅니다. 보관 tmux는 보드 터미널 화면에 대체 화면 없이 그려, 실행이 끝나도 마지막 출력이 터미널에 남고 일반 출력도 보드 기록 스크롤로 볼 수 있습니다. Claude Code·Codex처럼 마우스를 쓰는 화면은 휠이 그 앱으로 갑니다. 터미널을 닫으면(실행 종료·연결 닫기) 그 기기의 보관 실행도 끝내고, 그때 기기가 연결돼 있지 않으면 "실행 기기에 연결되면 그 기기의 실행도 종료합니다"라고 알린 뒤 기기가 돌아오면 정리합니다. 보드는 5분마다 자기가 만든 보관 실행만 살펴, 사용자가 닫았거나 보드가 정리한 터미널의 것은 바로, 스스로 끝난 터미널의 것이나 기록이 없는 것은 하루 뒤 정리합니다(다른 보드의 것은 건드리지 않음).
- tmux가 없는 기기나 PC에서는 실행이 SSH 연결 안에서 돌아, 그 기기가 2분 넘게 잠들면 연결이 끊기고 보드에서 새로 연 세션·다시 연 대화는 실행이 끝납니다(대화 기록은 남습니다). 기존 작업에 붙은 연결(attach)이 끊기면 보기만 끝나고 작업은 계속됩니다.
- 끝난 터미널에는 이유(10분 미사용으로 정리했는지, 실행 기기와의 연결이 끊겼을 수 있는지)와, 그 세션이 목록에 있으면 **이 세션 다시 열기** 버튼을 보여 줍니다. 다시 열기는 새 터미널처럼 실행 계획을 확인한 뒤 엽니다.
- 오래 백그라운드에 있던 화면(홈 화면 앱 등)이 다시 보이면, 브라우저가 온라인 알림을 놓쳤더라도 실제로 연결돼 있으면 오프라인 표시를 풀고 목록·대화를 다시 읽으며 실시간 연결도 새로 시작합니다.
- 보드 터미널은 기본 16개(`--max-terminals`로 1~32)까지 동시에 엽니다. 가득 찬 상태에서 새 터미널을 열면 기존 세션에 붙은 연결(`연결 닫기`로 닫을 수 있는 attach 연결) 중 1분 넘게 화면 읽기·입력이 없던 가장 오래된 연결을 닫고 자리를 만듭니다. 이 정리는 보드의 연결만 닫으며 기존 세션에 중단 명령을 보내지 않고, 사용자 종료로 기록하지 않아 그 세션의 재개를 막지 않습니다. 다음 입력 때 **터미널 열기**로 다시 연결합니다. 보드에서 직접 실행한 새 세션·인계·이전·재개 터미널과 실행 준비 중인 터미널은 자동으로 닫지 않으며, 정리할 연결이 없으면 열린 터미널 수와 함께 안내합니다.
- 보내기·질문 불러오기로 보드가 연 Claude 세션 연결은 10분 동안 화면 읽기·입력이 없으면 공간과 상관없이 닫습니다(세션은 계속 실행). Codex 연결은 터미널이 가득 찼을 때만 정리합니다. 열린 터미널 시트에서는 이 연결들을 "세션 연결 N개" 한 줄로 접어 두고, 사용자가 연 터미널만 바로 보여 줍니다.
- 새 세션 터미널이 실제로 무엇을 실행하는지는 그 기기의 프로세스 목록(`ps`, 보드 사용자의 프로세스만)에서 터미널을 연 시각에 시작된 실행기 아래의 첫 CLI로 읽습니다(기기마다 1분에 한 번, 화면을 기다리게 하지 않음). Claude 에이전트 목록(`claude agents`)이면 "Claude 에이전트 목록 · 폴더"로 이름을 붙이고, 같은 기기·같은 폴더의 목록 화면이 두 개 이상이면 나중 것에 "같은 화면이 이미 열려 있어요"를 표시합니다. 실행기를 하나로 특정할 수 없으면 추정하지 않습니다. 새 세션 시트는 그 기기에 이미 열린 새 세션 터미널을 함께 보여 주어 같은 화면을 다시 열지 않게 합니다. Windows 기기는 아직 읽지 않습니다.
- 열린 터미널의 이름은 보드가 그 터미널의 세션을 알면 그 세션의 표시 제목(제목 수정 포함)을 따르고, 새 목록을 받을 때 함께 바뀝니다. 세션을 알 수 없는 새 세션 터미널은 실행기 이름과 연 시각으로 구분합니다. Claude의 `claude agents`처럼 한 터미널이 여러 세션을 관리하는 실행기는 특정 세션 하나로 연결하지 않습니다.

- 입력 요청 ID와 내용의 해시를 로컬 SQLite에 먼저 기록한 뒤 PTY에 씁니다. 입력 원문은 이 기록에 저장하지 않습니다. 부분 입력 실패·응답 유실·서버 재시작 뒤 같은 요청은 다시 입력하지 않으며, 결과 미확인은 실제 터미널에서 확인해야 합니다.
- 기록은 최대 25만 건, 데이터베이스는 최대 64 MiB입니다. 한도에 도달하면 새 입력을 거절합니다. 실행 종료를 확인한 터미널의 기록은 해당 터미널을 닫거나 목록을 새로 읽을 때 정리합니다. 살아 있는 터미널의 기록을 시간만으로 삭제하지 않습니다.
- 하나의 상태 폴더는 보드 프로세스 하나만 사용합니다. 포트만 바꿔 같은 상태 폴더로 두 보드를 실행할 수 없습니다.

## 검증 상태

- 원본 개인 개발 환경에서는 Codex CLI 0.161.0과 0.160.1의 격리 세션 검증 기록이 있습니다. 이 기록은 현재 공개 후보 빌드에서의 재검증이나 해당 버전만의 지원 보증이 아닙니다.
- 공개 후보 자체의 CLI 버전별 호환성, 다양한 macOS·네트워크 구성, 실제 사용자 데이터 이전은 아직 독립적으로 확인되지 않았습니다.
- 이전 개인 모바일 검수는 특정 기기의 일부 파일 첨부·입력 동작에 한정됩니다. 공개 후보의 모바일 브라우저 전반, 클립보드 권한, 키보드·IME, 잠금과 망 전환을 입증하지 않습니다.
- 자동 테스트, fixture, echo 터미널 검증은 실제 사용자 계정·모델 turn·모바일 하드웨어 검증을 대신하지 않습니다.

지원 범위는 native CLI와 OS 버전에 따라 달라질 수 있습니다. 새 버전으로 갱신하기 전에는 별도 테스트 계정과 합성 작업공간으로 확인하세요.
