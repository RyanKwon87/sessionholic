# 지원 범위와 한계

세션홀릭(Sessionholic)은 개인이 소유한 macOS 중심 환경에서 로컬 native CLI 세션을 모아 보고, 기존 세션에 연결하거나 새 환경에서 맥락을 이어가는 self-hosted 도구입니다. 여러 사용자가 공유하는 서비스나 공개 인터넷 서비스가 아닙니다. 각 호스트에는 사용자가 직접 설치하고 로그인한 Claude Code 또는 Codex CLI, Python, tmux가 필요합니다. 호스트 간 기능은 사용자가 설정한 SSH 연결을 사용합니다.

## 세션 조회와 연결

- 작업 목록은 프로젝트·제목·기기·상태를 구분해 보여줍니다. 프로젝트명은 호스트 설정의 라벨이나 기록된 작업 폴더 이름을 사용하고, 짧은 폴더 힌트로 작업 위치를 구분합니다. 제목과 대화 미리보기는 원본 CLI의 값을 사용하므로 현재 작업 내용과 갱신 시점이 다를 수 있습니다.
- 수집기는 설치된 CLI의 로컬 세션 정보를 읽습니다. 세션 형식이나 CLI 동작이 바뀌면 조회·재연결이 제한될 수 있습니다. 오프라인 호스트에서는 마지막으로 저장한 결과가 보일 수 있으며, 오래된 값은 현재 상태로 간주하면 안 됩니다.
- 연결에 실패한 기기는 화면이 열려 있는 동안 2분·5분·15분(이후 15분마다)이 지난 뒤 자동으로 다시 확인합니다. 그 사이에는 반복 접속하지 않으며, 새로고침 버튼은 즉시 다시 확인합니다.
- 같은 탭에서 다시 연 대화는 메모리에 남은 내용을 먼저 보여주고 최신 기록을 확인합니다. 확인 중이거나 연결이 끊긴 경우 이를 표시하며, 기기·계정·세션·작업 폴더가 다르면 이 내용을 재사용하지 않습니다. 잠금이나 인증 만료 시 메모리의 대화도 지웁니다.
- Codex 연결은 확인된 로컬 daemon 세션과 정확한 세션 식별자를 사용합니다. vendor의 cloud Remote 세션, 불명확한 ID, 또는 필요한 daemon 연결이 없는 세션을 임의로 재개하지 않습니다.
- Claude background 세션은 exact attach를 지원합니다. 기존 interactive 세션의 직접 attach는 지원하지 않으며 native 터미널을 사용해야 합니다.
- 계정 전환과 새 세션 생성은 대상 호스트에 이미 준비되어 있는 계정을 사용합니다. 로그인 자격증명이나 provider 설정을 다른 호스트로 복사하지 않습니다.

## 메시지와 첨부

- 에이전트 답변은 기본 Markdown 서식(제목·문단·목록·인용·강조·코드·HTTP(S) 링크)으로 표시합니다. 목록 항목은 들여쓴 이어지는 줄, 빈 줄로 띄운 항목·하위 항목, 들여쓴 코드 펜스를 같은 항목으로 묶습니다. 문단 중간의 번호 줄은 `1.`로 시작할 때만 목록이 되고, `2026. 10. 10.` 같은 날짜 줄은 목록으로 보지 않습니다. 코드 블록은 위쪽 머리 줄에 언어와 복사 버튼을 둡니다. 본문 복사는 인용·강조 기호를 제거하고 링크 주소를 남기며, 코드 복사는 문자·들여쓰기·줄바꿈을 보존합니다. 사용자 입력과 native 대화 원문은 수정하지 않습니다.
- 보드 대화는 메시지당 4,000자까지만 받아 표시합니다. 잘린 메시지에는 일부만 표시됐다는 안내가 붙으며, 전체 내용은 원본 native 세션에서 확인해야 합니다. 코드 블록 중간에서 잘리면 끝의 " …"가 코드의 일부로 보일 수 있습니다.
- HTML과 외부 이미지는 실행하거나 불러오지 않습니다. 표·구분선·참조 링크·맨 URL 자동 링크 등은 완전한 Markdown 렌더링을 지원하지 않으며 텍스트로 남습니다. 답변이 65,536자·1,024행을 넘거나 파싱 한도에 도달하면 전체 원문을 텍스트로 표시하고 복사합니다.
- 사용자·에이전트 메시지 사이에 이어진 도구 실행 기록은 "도구 실행 7개 · 명령 4 · 파일 수정 2" 같은 한 줄로 접어 둡니다. 누르면 기록이 한 줄씩 펼쳐지고, 긴 기록은 한 번 더 눌러 전체를 봅니다. 펼친 상태는 새 메시지가 와도 유지되며, 길게 누르기 메뉴로 묶음 전체를 복사할 수 있습니다. 서버가 보내는 최근 80행에는 도구 기록도 포함되므로, 도구 실행이 많은 대화는 더 이른 대화가 먼저 잘립니다.
- Codex 기록에는 항목별 시각이 없고 turn의 시작·완료 시각만 있습니다. 그래서 turn의 첫 질문에는 시작 시각, 최종 답에는 완료 시각을 표시하고, 중간 보고·작업 중 추가 입력·도구 기록에는 시각을 표시하지 않습니다.
- 대화 끝의 "··· 작업 중"은 세션이 작업 중이고 화면의 마지막 행이 사용자 메시지(보드에서 막 보낸 말풍선 포함)나 도구 실행 묶음일 때만 표시합니다. 에이전트 답이나 시스템 행이 마지막이면 표시하지 않습니다. Claude 백그라운드 세션은 답을 낸 뒤에도 도구·하위 작업이 남으면 계속 작업 중이기 때문입니다. 세션 상태는 입력창 위 상태 문구와 목록 배지에 그대로 표시합니다. 아직 읽은 기록이 없으면(ID 없는 Claude 세션 등) 세션 상태만으로 표시합니다.
- 경과 시간("작업 중 · 12분 34초", 1시간 이상은 시·분)은 정확한 시작 시각이 있는 Codex(진행 중인 turn의 시작 시각)만 표시합니다. Claude는 turn 시작을 기록하지 않아 서버가 마지막 사용자 요청 시각으로 근사하므로 시간 없이 "작업 중"만 표시합니다. 표시가 숨거나 화면이 숨겨지면 갱신을 멈춥니다.
- Claude Code가 `[Request interrupted by user]`·대화 요약(`/compact`)·`!` 셸 명령을 사용자 줄로 기록한 것은 "사용자가 중단함"·"이전 대화 요약으로 이어짐" 안내와 명령 기록으로 표시합니다. `claude agents`가 ID 없이 보여 주는 대화형 세션은 대화를 읽거나 보낼 수 없어 안내 한 줄만 표시합니다.
- 입력창은 기본 1~6줄로 늘어나고 펼치면 최대 11줄까지 사용합니다. 실제 높이는 키보드를 제외한 화면 높이에 맞춰 제한되며 긴 초안은 입력창 안에서 스크롤합니다. 접으면 한 줄로 줄어들고 다시 입력하면 자동 확장됩니다.
- 사용자 메시지의 첨부 여부·개수를 표시하며, 전송 기록과 native 입력이 일치하는 파일은 이름·크기도 표시합니다. 보드가 파일을 보낼 때 덧붙인 `첨부 파일: <경로>` 줄은 말풍선과 복사에서 빼고 파일 이름 칩으로 보여 줍니다. 이전 기록이나 native에서 형식이 변환된 이미지는 이름을 추측하지 않고 일반 이미지 표시로 남깁니다. 전송 전 업로드, 전송 결과 미확인, 접수, 세션 기록 확인은 구분합니다. 기록 확인은 에이전트가 파일 내용을 검토했다는 뜻이 아닙니다.
- 웹 첨부의 이름·크기·종류와 입력 해시는 실행 호스트의 비공개 수신 기록에 보관합니다. 대화 본문·파일 내용·경로는 이 표시용 기록에 저장하지 않습니다. 기기 간 새 세션으로 이전할 때 원본 요청 ID의 첨부 표시 기록을 임의로 연결하지 않습니다.
- Codex 직접 메시지는 native app-server의 `turn/start` 하나로 보냅니다. 세션이 쉬고 있으면 새 turn이 시작되고, 작업 중이면 진행 중인 turn에 입력이 합류해 CLI가 다음 차례에 반영합니다. 보드는 메시지를 따로 예약하거나 대기열에 넣지 않습니다. `/review`·수동 `/compact`처럼 입력을 받을 수 없는 turn이면 보내지 않은 것으로 확정하고 초안을 남깁니다. 직접 입력 가능 여부(`canAcceptDirectInput`)는 실험적 필드라 CLI 업데이트 후 달라질 수 있으며, 처음 보는 turn 상태가 있으면 대화는 계속 보여 주되 입력을 잠급니다.
- 보드 대화는 원본 세션의 기록을 다시 읽어 갱신합니다. 작업 중에는 3초 간격으로 시작해 5·10·20초로 간격을 늘리며 최대 240회 확인하고, 일시 오류 뒤에도 같은 간격으로 다시 확인합니다. 그 뒤에는 상태 다시 확인이나 당겨서 새로고침을 사용합니다. cmux 등의 native 터미널 화면 갱신은 해당 클라이언트가 담당하므로 웹과 표시 시점이 다를 수 있습니다. [OpenAI app-server 문서](https://learn.chatgpt.com/docs/app-server)도 `thread/read`를 이벤트 구독 없이 기록을 읽는 호출로 설명합니다.
- Claude CLI에는 기존 세션에 메시지만 보내는 명령이 없어, 보드가 그 세션에 연결한 tmux 터미널에 붙여넣고 Enter를 보냅니다. 보드는 터미널을 스스로 열지 않습니다. 백그라운드 세션에 보드 터미널이 없으면 입력창에 "보내려면 먼저 터미널을 여세요." 안내와 **터미널 열기** 버튼이 나오고, 사용자가 이 버튼(또는 질문 카드의 "질문 불러오기")으로 `claude attach` 터미널을 연 뒤 보낼 수 있습니다. 초안은 그동안 써 둘 수 있고, 그 사이 터미널이 닫혀 거절되면 보내지 않은 것으로 확정하고 초안을 남깁니다. 보드 밖 터미널 앱에서 직접 실행 중인 Claude 세션은 웹에서 입력할 수 없습니다. 터미널 화면에 승인·질문 선택 메뉴(`❯ 1.` 형식)가 떠 있으면 입력이 메뉴 선택으로 처리될 수 있어 보내지 않습니다. 같은 요청은 다시 붙여넣지 않으며, 본문 대신 앞부분의 해시만 보관해 대화 기록에서 반영 여부를 확인합니다.
- 승인·질문 메뉴는 보드가 그 세션에 연결한 터미널 화면에서 읽어 대화 화면의 질문 카드로 보여 줍니다. 선택지를 고른 뒤 보내기를 따로 눌러야 하고, 보내기 직전에 화면을 다시 읽어 같은 메뉴일 때만 방향키와 Enter를 입력합니다. 여러 개를 고르는 메뉴, 현재 선택 위치를 알 수 없는 메뉴, 보드 밖 터미널에서 실행 중인 세션은 터미널에서 답해야 합니다. 화면 형식은 CLI 버전에 따라 달라질 수 있습니다. 같은 세션의 보드 터미널로 돌아갈 때는 확인 창 없이 바로 연결합니다.
- 결과가 불명확한 메시지는 자동으로 다시 보내지 않습니다. 수신 여부를 먼저 확인하고, 같은 요청을 반복 제출하지 마세요.
- 서버가 native 전송 전 거절을 확인한 경우에는 초안과 첨부를 남기고 입력 잠금을 해제합니다. HTTP 오류 번호만으로 미전송을 추정하지 않습니다. 잠그기와 인증 만료는 대화·초안을 지우는 별도 보안 동작입니다.
- 텍스트는 메시지당 UTF-8 32 KiB, 첨부 파일은 개별 20 MiB, 메시지당 8개까지입니다. 첨부 파일은 실제 세션의 작업 폴더 아래 보드 관리 디렉터리(`.sessionholic-attachments/`)에 저장됩니다. 작업 폴더가 Git 저장소 안이면 이 디렉터리를 저장소의 `info/exclude`에 한 번 추가해 `git add -A`에 포함되지 않게 합니다. 이 처리는 최선 노력이라 실패해도 업로드는 진행되며, 이미 추적 중이거나 강제로 추가한 파일은 막지 않습니다. 보통 파일은 내용 전체를 메시지에 삽입하는 대신 native CLI가 읽을 수 있는 경로로 전달합니다.

## 인계와 기기 간 이전

- 같은 native 세션에 연결하는 경우 기존 프로세스를 사용합니다. 도구·계정 변경을 위한 인계는 최근 대화와 Git 상태 등의 맥락을 전달해 **새 native CLI 세션**을 실행합니다. 원본 프로세스, 실행 중인 turn, 승인 상태를 새 호스트로 옮기는 기능이 아닙니다.
- 기기 간 이전은 원본 응답을 확인하고 중단한 뒤 선택된 작업공간 파일과 최근 대화를 새 목적 폴더로 복사하고 대상 호스트에서 새 세션을 준비합니다. 원본 파일과 기록은 남겨 둡니다. 이는 프로세스 이동이나 완전한 복원 기능이 아닙니다.
- 작업공간 아카이브는 최대 128 MiB, 파일 항목은 최대 20,000개입니다. Git 저장소에서는 Git이 무시하는 폴더와 중첩 저장소·worktree를 세지 않고 복사하지 않습니다. Git이 아닌 폴더에서는 빌드 결과물·의존성·도구 캐시 폴더(`node_modules`, `Pods`, `.gradle`, Cargo·Maven `target` 등)를 제외합니다.
- 이전은 알려진 자격증명과 특수 파일을 제외하고 제한된 크기의 작업공간을 복사합니다. 인증 파일(`.env`, `auth.json`, 개인키, `.ssh` 등)과 프로젝트 `.claude`·`.codex` 폴더의 개인 설정·세션 기록은 복사하지 않고, 공유 설정(`agents`, `commands`, `skills`, `hooks`, `settings.json`, `AGENTS.md`)은 복사합니다. 이름이 자격증명처럼 보이는 미추적 파일(`token`·`secret`·`credential`이 들어간 데이터 파일, `secrets/`, `*.key`, `.envrc`, `*.tfvars` 등)은 제외하고 미리보기에 목록과 경고를 표시합니다. 두 종류 모두 Git이 추적하거나 HEAD 이력에 있으면 번들 이력에 포함되므로 이전 전체를 거절합니다.
- 제외 규칙이 모든 비밀정보를 식별한다고 보장할 수 없습니다. 미리보기의 큰 파일·제외 파일 목록과 경고를 검토하고, 민감한 정보가 없는지 확인하세요.
- 원본이 이전 중 다시 변경되거나 대상이 준비되지 않으면 새 세션 실행을 중단합니다. 이미 중단된 원본 응답은 자동으로 재개하지 않습니다.
- 대상 준비 요청의 응답이 유실되면 이미 대상 작업이 시작됐을 수 있습니다. 보드는 결과를 미확인 상태로 기록하고 같은 요청을 자동 재실행하지 않습니다. 대상 기기의 작업 목록과 이전 기록을 확인한 뒤 다음 작업을 진행하세요. 대상 도우미가 새 세션 연결 전 단계(검증·파일 복원·실행 준비)에서 실패를 직접 보고한 경우에는 그 원인을 실패로 기록하고 대상 임시 파일을 정리합니다.
- 터미널 연결 자리는 대상 실행 준비 전에 확보합니다. 이후 연결 자체가 실패할 수 있으며, 이때는 대상 기기와 준비된 세션 정보를 안내합니다. 새 인계 계획을 명시적으로 실행하면 별도 작업이 만들어질 수 있으므로 먼저 대상 목록을 확인하세요. 모든 단계의 자동 복구를 제공하는 것은 아닙니다.

## 터미널 입력과 상태 기록

- 휴대폰 등 터치 기기의 대화 화면에서는 대화를 위·아래로 스크롤하기 시작하면 위·아래 메뉴가 접히고, 맨 아래에 닿아도 다시 펼치지 않습니다. 대화를 한 번 탭하면 펼치고 다시 탭하면 접습니다. 버튼·링크·코드 복사·질문 카드·첨부를 누르거나 길게 눌러 메뉴를 열면 그 동작만 합니다. 새 질문 카드, 전송 결과, 연결 오류는 메뉴를 자동으로 펼칩니다. 입력창을 누르면 입력용 접힘 화면이 되고, 입력을 마치면 그 전의 펼침·접힘으로 돌아갑니다. 마우스를 쓰는 화면은 이전처럼 위로 읽으면 접히고 맨 아래에서 펼쳐집니다. 제스처 판정 값은 `web/app.js`의 `GESTURE` 한곳에 있습니다.
- 휴대폰 등 터치 기기에서는 xterm 화면에 직접 입력하지 않고 아래 입력줄을 사용합니다. 모바일 키보드의 한글 조합과 음성 입력은 단어 전체를 다시 쓰는 방식이라 터미널로 반복 전송될 수 있기 때문입니다. 입력줄의 보내기는 한 번 붙여넣은 뒤 Enter를 따로 보내고, 입력은 Enter 없이 붙여넣기만 합니다. 설정에서 터미널 화면 직접 입력을 다시 켤 수 있습니다.
- 특수키는 두 줄(Esc·Tab·⇧Tab·Ctrl+C/J/U/X/L, 역T자 방향키, Enter)입니다. 화면을 쓸어 넘기거나 휠을 돌리면, 대체 화면을 쓰며 마우스를 받는 CLI(Claude·Codex 화면 등)에는 휠 신호를 보내 CLI가 스스로 스크롤하게 하고, 그 밖의 화면은 tmux 기록(최대 2만 줄)을 스크롤합니다. 손가락을 튕기면 관성으로 이어지며, 기록을 보는 동안 실시간으로 돌아가는 버튼이 표시됩니다.
- 출력 연결이 끊기면 최대 6회까지 자동으로 다시 읽습니다. 입력은 결과가 불확실하면 다시 보내지 않습니다.

- 입력 요청 ID와 내용의 해시를 로컬 SQLite에 먼저 기록한 뒤 PTY에 씁니다. 입력 원문은 이 기록에 저장하지 않습니다. 부분 입력 실패·응답 유실·서버 재시작 뒤 같은 요청은 다시 입력하지 않으며, 결과 미확인은 실제 터미널에서 확인해야 합니다.
- 기록은 최대 25만 건, 데이터베이스는 최대 64 MiB입니다. 한도에 도달하면 새 입력을 거절합니다. 실행 종료를 확인한 터미널의 기록은 해당 터미널을 닫거나 목록을 새로 읽을 때 정리합니다. 살아 있는 터미널의 기록을 시간만으로 삭제하지 않습니다.
- 하나의 상태 폴더는 보드 프로세스 하나만 사용합니다. 포트만 바꿔 같은 상태 폴더로 두 보드를 실행할 수 없습니다.

## 검증 상태

- 원본 개인 개발 환경에서는 Codex CLI 0.161.0과 0.160.1의 격리 세션 검증 기록이 있습니다. 이 기록은 현재 공개 후보 빌드에서의 재검증이나 해당 버전만의 지원 보증이 아닙니다.
- 공개 후보 자체의 CLI 버전별 호환성, 다양한 macOS·네트워크 구성, 실제 사용자 데이터 이전은 아직 독립적으로 확인되지 않았습니다.
- 이전 개인 모바일 검수는 특정 기기의 일부 파일 첨부·입력 동작에 한정됩니다. 공개 후보의 모바일 브라우저 전반, 클립보드 권한, 키보드·IME, 잠금과 망 전환을 입증하지 않습니다.
- 자동 테스트, fixture, echo 터미널 검증은 실제 사용자 계정·모델 turn·모바일 하드웨어 검증을 대신하지 않습니다.

지원 범위는 native CLI와 OS 버전에 따라 달라질 수 있습니다. 새 버전으로 갱신하기 전에는 별도 테스트 계정과 합성 작업공간으로 확인하세요.
